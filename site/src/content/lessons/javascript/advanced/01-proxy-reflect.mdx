[Property descriptors](../../intermediate/property-descriptors/) change what one property does, and [well-known symbols](../../intermediate/symbols/) such as `Symbol.iterator` let an object join a language protocol, one property or protocol at a time.

A **proxy** goes further. It wraps an object and intercepts the basic operations on it: reading any property, even an undefined one, assigning, `in`, `delete`, listing keys, and calling. Proxies and `Reflect` are ES2015 and run on every supported Node version.

## A first proxy

`new Proxy(target, handler)` wraps the **target**. The **handler**'s methods, called **traps**, replace the default behaviour of an operation; an operation with no trap goes straight to the target.

```javascript title="proxy_basics.mjs"
const target = { name: "Ada" };

const withDefault = new Proxy(target, {
  get(obj, key) {
    return key in obj ? obj[key] : "(none)";
  },
});

console.log(withDefault.name, withDefault.email);
console.log(target.email);

withDefault.email = "ada@example.com";
console.log(target.email, withDefault === target);
```

```text
Ada (none)
undefined
ada@example.com false
```

- The `get` trap decides what a read returns: a missing property now reads as `"(none)"`.
- The target is untouched: `target.email` is still `undefined`.
- With no `set` trap, the assignment falls through to the target.
- The proxy is a different object, and code that holds the target bypasses every trap.

## Traps and the operations behind them

The specification defines every object operation through 13 **internal methods**, such as `[[Get]]` and `[[OwnPropertyKeys]]`, and a proxy has one trap for each:

| Trap | Triggered by |
|---|---|
| `get`, `set` | reading and assigning a property |
| `has` | the `in` operator |
| `deleteProperty` | `delete` |
| `ownKeys` | `Object.keys`, `Reflect.ownKeys`, `for...in`, spread |
| `getOwnPropertyDescriptor`, `defineProperty` | the descriptor functions, and parts of other operations |
| `getPrototypeOf`, `setPrototypeOf` | prototype reads and changes, `instanceof` |
| `isExtensible`, `preventExtensions` | the extensibility checks and `Object.preventExtensions` |
| `apply`, `construct` | calling a function, and `new` (function targets only) |

Many operations use several internal methods; to see which, log them. **`Reflect`** is a built-in object with one function per trap, with the same name and parameters, each doing exactly what the default operation does. That makes a logging handler short:

```javascript title="trap_log.mjs"
const names = ["get", "set", "has", "deleteProperty", "ownKeys",
  "getOwnPropertyDescriptor", "defineProperty"];
let seen = [];
const handler = {};
for (const name of names) {
  handler[name] = (...args) => {
    seen.push(name);
    return Reflect[name](...args);
  };
}

const p = new Proxy({ a: 1, b: 2 }, handler);
function show(label) {
  console.log(label.padEnd(14), seen.join(", "));
  seen = [];
}
```

```javascript title="trap_log.mjs (continued)"
p.a;
show("read");
p.c = 3;
show("assign");
"a" in p;
show("in");
delete p.b;
show("delete");
Object.keys(p);
show("Object.keys");
```

```text
read           get
assign         set, getOwnPropertyDescriptor, defineProperty
in             has
delete         deleteProperty
Object.keys    ownKeys, getOwnPropertyDescriptor, getOwnPropertyDescriptor
```

Two surprises. An assignment fires `set`, then `getOwnPropertyDescriptor` and `defineProperty`: the default `[[Set]]` checks the property and then defines it on the receiver, which is the proxy. `Object.keys` reads each key's descriptor to skip non-enumerable keys. Logging shows what your traps will see.

## Reflect and the receiver

The `get` and `set` traps receive a third argument, the **receiver**: the object the operation started on, normally the proxy. For a getter or setter, the receiver becomes `this`. Compare forwarding with `obj[key]` and with `Reflect.get(obj, key, receiver)`:

```javascript title="receiver.mjs"
const person = {
  first: "Grace",
  get greeting() {
    return `Hello, ${this.nickname}`;
  },
};

const naive = new Proxy(person, {
  get(obj, key) {
    return key in obj ? obj[key] : "friend";
  },
});
console.log(naive.greeting);
```

```text
Hello, undefined
```

```javascript title="receiver.mjs (continued)"
const correct = new Proxy(person, {
  get(obj, key, receiver) {
    return key in obj ? Reflect.get(obj, key, receiver) : "friend";
  },
});
console.log(correct.greeting);
```

```text
Hello, friend
```

With `obj[key]`, the getter runs with `this` set to the target, so `this.nickname` skips the proxy and finds nothing. `Reflect.get` with the receiver runs it with `this` set to the proxy, so the getter's own read goes through the trap. The rule: **forward with `Reflect` and pass every argument the trap received**. It also covers objects that inherit from a proxy.

`Reflect` also reports failure differently: `Reflect.defineProperty` returns `false` where `Object.defineProperty` throws, and `Reflect.set` returns whether the assignment worked. Traps such as `set` and `defineProperty` must return a boolean, so the `Reflect` result is exactly what to pass back.

```javascript title="reflect_booleans.mjs"
const frozen = Object.freeze({ id: 1 });

console.log(Reflect.set(frozen, "id", 2), frozen.id);
console.log(Reflect.defineProperty(frozen, "extra", { value: 1 }));

try {
  Object.defineProperty(frozen, "extra", { value: 1 });
} catch (error) {
  console.log(error.name);
}
console.log(Reflect.ownKeys({ a: 1, [Symbol("s")]: 2 }));
```

```text
false 1
false
TypeError
[ 'a', Symbol(s) ]
```

`Reflect.ownKeys` lists string and symbol keys together, enumerable or not, which is what the `ownKeys` trap must return.

## A validating model

The most common use of a proxy is checking values as they are assigned. Here the rules live in a schema: a property it names is checked, and any other is refused.

```javascript title="validating_model.mjs"
function model(schema, initial) {
  return new Proxy({ ...initial }, {
    set(obj, key, value, receiver) {
      const check = schema[key];
      if (!check) {
        throw new TypeError(`unknown field "${String(key)}"`);
      }
      if (!check(value)) {
        throw new TypeError(`bad value for "${key}": ${value}`);
      }
      return Reflect.set(obj, key, value, receiver);
    },
  });
}
```

```javascript title="validating_model.mjs (continued)"
const user = model(
  { name: (v) => typeof v === "string", age: Number.isInteger },
  { name: "Ada", age: 36 },
);

user.age = 37;
console.log(user.name, user.age);

for (const [key, value] of [["age", 37.5], ["email", "a@b.c"]]) {
  try {
    user[key] = value;
  } catch (error) {
    console.log(error.message);
  }
}
```

```text
Ada 37
bad value for "age": 37.5
unknown field "email"
```

`String(key)` turns a symbol key into text, since a template literal throws on a symbol. The initial values are spread into a fresh target, so nobody holds a reference to the unchecked object.

The same trap can report a change instead of refusing it, which is the core of an **observable** object:

```javascript title="observable.mjs"
function observable(target, onChange) {
  return new Proxy(target, {
    set(obj, key, value, receiver) {
      const old = obj[key];
      const ok = Reflect.set(obj, key, value, receiver);
      if (ok && old !== value) {
        onChange(key, old, value);
      }
      return ok;
    },
  });
}

const cart = observable({ items: 0 }, (key, from, to) => {
  console.log(`${key}: ${from} -> ${to}`);
});
cart.items = 2;
cart.items = 2;
cart.items += 1;
```

```text
items: 0 -> 2
items: 2 -> 3
```

The second assignment stores the same value, so nothing is reported. Nested changes are missed: `cart.address.city = "Oslo"` reads `address` through the proxy, then assigns on the plain inner object. Watching nested data means wrapping each object as it is read.

## Invariants: the rules a trap cannot break

A trap may answer almost anything, but not everything. **Invariants** keep a proxy consistent with its target, mostly for non-configurable, non-writable properties and non-extensible targets: what the target promises must still hold through the proxy. A trap that breaks one makes the operation throw a `TypeError`.

```javascript title="invariants.mjs"
const target = {};
Object.defineProperty(target, "id", { value: 1, writable: false });

const liar = new Proxy(target, {
  get: () => 99,
  has: () => false,
});

for (const attempt of [() => liar.id, () => "id" in liar]) {
  try {
    console.log(attempt());
  } catch (error) {
    console.log(error.name);
  }
}
console.log(new Proxy({ id: 1 }, { get: () => 99 }).id);
```

```text
TypeError
TypeError
99
```

`id` was defined with `defineProperty`, so it is non-writable and non-configurable ([the descriptor defaults](../../intermediate/property-descriptors/)). A `get` trap may not report another value for it, and a `has` trap may not hide it; on an ordinary property both lies are allowed. To proxy a frozen object, give the proxy a different target and look values up elsewhere.

## Proxying functions

When the target is a function, the `apply` trap intercepts calls and `construct` intercepts `new`. `Reflect.apply(fn, thisArg, args)` performs the call.

```javascript title="function_proxy.mjs"
function counted(fn) {
  let calls = 0;
  const proxy = new Proxy(fn, {
    apply(target, thisArg, args) {
      calls += 1;
      return Reflect.apply(target, thisArg, args);
    },
  });
  return { proxy, count: () => calls };
}

const { proxy: max, count } = counted(Math.max);
console.log(max(3, 9, 4), max(1), count());
console.log(max.name, max.length);
```

```text
9 1 2
max 2
```

Only `apply` is trapped, so `max.name` and `max.length` read from the target. A plain wrapper such as `(...args) => fn(...args)` counts just as well, and faster; a function proxy earns its place when the wrapper must look exactly like the original.

## Revocable proxies

`Proxy.revocable(target, handler)` returns a proxy and a `revoke` function. After `revoke()`, every operation on the proxy throws a `TypeError`, which lets you hand out access for a limited time, such as to a plugin during set-up.

```javascript title="revocable.mjs"
const { proxy: settings, revoke } = Proxy.revocable({ theme: "dark" }, {});

console.log(settings.theme);
revoke();

try {
  console.log(settings.theme);
} catch (error) {
  console.log(error.name);
}
```

```text
dark
TypeError
```

## Where proxies break

A proxy is a separate object, and some things refuse to work through one.

**Private fields.** A `#field` belongs to the object the constructor created. A method called through the proxy runs with `this` set to the proxy, and the private read fails: [private elements](../../intermediate/private-and-static/) are not properties, so no trap can forward them.

```javascript title="proxy_limits.mjs"
class Account {
  #balance = 100;
  get balance() {
    return this.#balance;
  }
}

const viaProxy = new Proxy(new Account(), {});
try {
  console.log(viaProxy.balance);
} catch (error) {
  console.log(error.name);
}
```

```text
TypeError
```

**Built-ins with internal slots.** A `Map`, `Set`, `Date` or promise keeps its data in an internal slot that only the real object has, so `Map.prototype.get` with the proxy as `this` fails too. A `get` trap that binds methods to the target works around it:

```javascript title="proxy_limits.mjs (continued)"
const plain = new Proxy(new Map([["a", 1]]), {});
try {
  console.log(plain.get("a"));
} catch (error) {
  console.log(error.name);
}

const bound = new Proxy(new Map([["a", 1]]), {
  get(map, key) {
    const value = Reflect.get(map, key, map);
    return typeof value === "function" ? value.bind(map) : value;
  },
});
console.log(bound.get("a"), bound.size);
```

```text
TypeError
1 1
```

`size` is a getter on `Map.prototype`, so the trap passes the map itself as the receiver instead of the proxy.

**Identity.** `proxy === target` is `false`, so as a `Map` key or `Set` member a proxy is a different entry from its target. `instanceof` still works, through the default `getPrototypeOf`.

**The console.** `console.log` does not run a proxy's traps: Node shows the target's own contents, which may differ from what your code sees. Node 26 labels the output `Proxy(...)`; Node 22 and 24 print the target as a plain object.

## When not to use a Proxy

**It is slow on hot paths.** In one test run on Node 26, a read through a forwarding `get` trap was about 60 times slower than a plain read. Measure your own hot path, and keep proxies away from data a tight loop reads.

**It is hard to debug.** The behaviour lives in a handler far from the line that reads `user.age`, stack traces gain trap frames, and nobody can tell from `cart.items += 1` that a callback runs.

**It surprises other code**, as the previous section showed. A known set of properties is better served by setters or an explicit `validate()` call where data enters, read-only data by `Object.freeze`, call counting by a [wrapper function](../../beginner/higher-order-functions/), and protocols by well-known symbols.

Reach for a proxy when the set of keys is open-ended, when the wrapper must be indistinguishable from the original, or when interception is the tool's whole job: test doubles, change tracking, access control. Keep the handler small, and forward everything else with `Reflect`.

## Common pitfalls

- **Forwarding with `obj[key]`.** Getters and setters then run against the target. Use `Reflect.get(obj, key, receiver)`.
- **Not returning `true` from `set`, `deleteProperty` or `defineProperty`.** In a module a falsy return throws a `TypeError`. Return the `Reflect` result.
- **A template literal around a symbol key.** It throws. Use `String(key)`.
- **Proxying a frozen object to change what it reports.** The invariants forbid it. Use a different target.
- **Keeping a reference to the target.** Writes through it bypass every check.
- **Proxying private fields or built-ins.** Bind methods to the target, or avoid the proxy.

<Exercise title="Negative array indices">

Write `withNegativeIndex(array)`, which returns a proxy of the array where reading a negative integer index counts from the end, as `at()` does. Property keys arrive as strings, so check for a key that looks like a negative integer (a regular expression such as `/^-\d+$/` works). Every other read, including `length` and methods, must behave as normal. Wrap `["a", "b", "c", "d"]`, print the reads at `-1`, `-4`, `-5` and `0`, then print `length` and the result of calling `.map((s) => s.toUpperCase())` on the proxy. The expected output is `d a undefined a` and then `4 [ 'A', 'B', 'C', 'D' ]`.

<Solution>

The trap converts the key to a number only when it matches, and leaves everything else to `Reflect.get`, so `length` and `map` work. `map` itself reads `length` and the indexes `"0"` to `"3"` through the proxy, which also take the normal path.

```javascript title="negative_index.mjs"
function withNegativeIndex(array) {
  return new Proxy(array, {
    get(target, key, receiver) {
      if (typeof key === "string" && /^-\d+$/.test(key)) {
        return target[target.length + Number(key)];
      }
      return Reflect.get(target, key, receiver);
    },
  });
}

const letters = withNegativeIndex(["a", "b", "c", "d"]);
console.log(letters[-1], letters[-4], letters[-5], letters[0]);
console.log(letters.length, letters.map((s) => s.toUpperCase()));
```

```text
d a undefined a
4 [ 'A', 'B', 'C', 'D' ]
```

<Exercise title="A read-only view">

Write `readOnly(object)`, which returns a proxy that allows reads but refuses changes: its `set`, `deleteProperty` and `defineProperty` traps throw a `TypeError` with the message `read-only: KEY`, and nested objects come back wrapped as read-only views too. The original object must stay writable through its own reference. Test it with `const config = { port: 80, db: { host: "x" } }`: print `view.port` and `view.db.host`, try `view.port = 81`, `view.db.host = "y"` and `delete view.port` and print each error message, then set `config.port = 8080` on the original and print `view.port`. The expected output is `80 x`, then `read-only: port`, `read-only: host`, `read-only: port`, and finally `8080`.

<Solution>

Unlike `Object.freeze`, the view does not change the original, so the owner can still update it and the view sees the new value. Wrapping nested objects inside `get` is what stops `view.db.host = "y"`.

```javascript title="read_only_view.mjs"
function readOnly(object) {
  const refuse = (target, key) => {
    throw new TypeError(`read-only: ${String(key)}`);
  };
  return new Proxy(object, {
    get(target, key, receiver) {
      const value = Reflect.get(target, key, receiver);
      return typeof value === "object" && value !== null
        ? readOnly(value)
        : value;
    },
    set: refuse,
    deleteProperty: refuse,
    defineProperty: refuse,
  });
}
```

```javascript title="read_only_view.mjs (continued)"
const config = { port: 80, db: { host: "x" } };
const view = readOnly(config);
console.log(view.port, view.db.host);

const attempts = [
  () => { view.port = 81; },
  () => { view.db.host = "y"; },
  () => { delete view.port; },
];
for (const attempt of attempts) {
  try {
    attempt();
  } catch (error) {
    console.log(error.message);
  }
}
config.port = 8080;
console.log(view.port);
```

```text
80 x
read-only: port
read-only: host
read-only: port
8080
```

</Solution>

</Exercise>

<Exercise title="Catch typos on read">

Plain objects return `undefined` for a misspelled property, which hides bugs. Write `strict(object)`, a proxy whose `get` trap throws a `ReferenceError` with the message `no property "KEY"` when the key is missing (use `Reflect.has`), but lets symbol keys through unchanged so that tools which probe objects with symbols still work. Wrap `{ host: "localhost", port: 5432 }`, print `host` and `port`, then try to read `prot` and print the error's name and message. Finally print `JSON.stringify` of the proxy. The expected output is `localhost 5432`, then `ReferenceError no property "prot"`, then `{"host":"localhost","port":5432}`.

<Solution>

`JSON.stringify` asks for a `toJSON` method before it reads the properties. With a trap that threw on every missing key, that probe would fail, so the solution lets `toJSON` through as well. This is a typical proxy surprise: other code performs reads you did not expect, and the log handler from the lesson is how you find them.

```javascript title="strict_object.mjs"
function strict(object) {
  return new Proxy(object, {
    get(target, key, receiver) {
      const probe = typeof key === "symbol" || key === "toJSON";
      if (!probe && !Reflect.has(target, key)) {
        throw new ReferenceError(`no property "${key}"`);
      }
      return Reflect.get(target, key, receiver);
    },
  });
}

const db = strict({ host: "localhost", port: 5432 });
console.log(db.host, db.port);
try {
  console.log(db.prot);
} catch (error) {
  console.log(error.name, error.message);
}
console.log(JSON.stringify(db));
```

```text
localhost 5432
ReferenceError no property "prot"
{"host":"localhost","port":5432}
```

</Solution>

</Exercise>

## Summary

- `new Proxy(target, handler)` intercepts the basic operations on an object, one trap per internal method.
- `Reflect` does each default operation. Forward with it, pass the receiver, and return its boolean results.
- Proxies suit validation, change notification, defaults and controlled access; `Proxy.revocable` withdraws access.
- Invariants stop a trap from contradicting non-configurable properties and non-extensible targets.
- Private fields and built-ins with internal slots fail through a plain proxy, and a proxy is never its target.
- Proxies are slow and hide behaviour. Prefer setters, `Object.freeze`, wrappers or explicit validation when they are enough.
