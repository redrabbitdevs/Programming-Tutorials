Choosing what to run next is the core of control flow. The idea is explained in the [fundamentals lesson on conditionals](../../../fundamentals/beginner/conditionals/). This lesson shows how JavaScript writes it, and the few spots where it differs from what you may expect.

## if, else if and else

The condition goes in brackets, and the branch is a statement or a block. Always use a block, even for one line, so that adding a second line later does not silently fall outside the `if`.

```javascript title="if_else.mjs"
function describeTemperature(celsius) {
  if (celsius < 0) {
    return "freezing";
  } else if (celsius < 15) {
    return "cold";
  } else if (celsius < 25) {
    return "mild";
  } else {
    return "hot";
  }
}

for (const t of [-5, 10, 20, 31]) {
  console.log(t, describeTemperature(t));
}

const name = "";
if (name) {
  console.log("has a name");
} else {
  console.log("name is empty");
}
```

```text
-5 freezing
10 cold
20 mild
31 hot
name is empty
```

The chain is tested from the top, and the first true condition wins. Because each branch returns, the `else` keywords are not strictly needed, but they make the shape clear.

A condition does not have to be a boolean. JavaScript converts it using the **truthy and falsy** rules from the [coercion lesson](../coercion/): `false`, `0`, `""`, `null`, `undefined`, `NaN` and `0n` are falsy, and everything else is truthy. That is why `if (name)` is false for an empty string. It is also why `if (count)` is false when `count` is `0`, which is a classic bug when `0` is a valid value. Write the comparison you mean: `if (count !== undefined)` or `if (count > 0)`.

## Guard clauses

Deeply nested `if` statements are hard to read. A **guard clause** checks for a bad or special case first and returns right away, so the main path stays at the left edge.

```javascript title="guard_clauses.mjs"
function shippingCost(order) {
  if (order === null || order === undefined) {
    return 0;
  }
  if (order.items.length === 0) {
    return 0;
  }
  if (order.total >= 50) {
    return 0;
  }
  return 4.99;
}

console.log(shippingCost(null));
console.log(shippingCost({ items: [], total: 0 }));
console.log(shippingCost({ items: ["book"], total: 60 }));
console.log(shippingCost({ items: ["pen"], total: 3 }));
```

```text
0
0
0
4.99
```

Read top to bottom, each guard removes one case from consideration, and the last line handles what is left. The nested version of the same function would put the `4.99` three levels deep.

## The conditional operator

The **conditional operator** `condition ? a : b` is an expression. It evaluates to `a` when the condition is truthy and to `b` otherwise. Use it to choose a value, where an `if` statement would not fit.

```javascript title="ternary.mjs"
const age = 20;
const label = age >= 18 ? "adult" : "minor";
console.log(label);

const n = 0;
console.log(`${n} item${n === 1 ? "" : "s"}`);

const score = 72;
const grade = score >= 90 ? "A" : score >= 80 ? "B" : score >= 70 ? "C" : "F";
console.log(grade);
```

```text
adult
0 items
C
```

It works well inside template literals, as in the plural example. Chaining it, as the `grade` line does, is legal and reads acceptably for a short table. Once a chain needs more than two or three tests, switch to `if` statements. Do not use `? :` for side effects, such as `ok ? save() : warn()`. An `if` says that more clearly.

## switch

`switch` compares one value against several `case` labels. It is useful when many branches test the same value for equality.

```javascript title="switch_basic.mjs"
function dayType(day) {
  switch (day) {
    case "sat":
    case "sun":
      return "weekend";
    case "mon":
    case "tue":
    case "wed":
    case "thu":
    case "fri":
      return "weekday";
    default:
      return "unknown";
  }
}

console.log(dayType("sun"), dayType("wed"), dayType("xyz"));

const level = 2;
switch (level) {
  case 1:
    console.log("one");
  case 2:
    console.log("two");
  case 3:
    console.log("three");
    break;
  case 4:
    console.log("four");
}

switch ("5") {
  case 5:
    console.log("matched the number");
    break;
  default:
    console.log("strict comparison: no match");
}
```

```text
weekend weekday unknown
two
three
strict comparison: no match
```

Three behaviours to know:

- **Matching uses strict equality (`===`).** The string `"5"` does not match `case 5`, as the last block shows.
- **Cases fall through.** Execution continues into the next `case` until it meets `break`, `return` or the end of the `switch`. In the second block `level` is 2, so it prints `two` and also `three`. Falling through on purpose is how `"sat"` and `"sun"` share one result in `dayType`. Falling through by accident, from a missing `break`, is a frequent bug.
- **`default` runs when nothing else matches.** It may go anywhere, but last is the convention.

All the cases share one block scope. If you need a `let` or `const` inside a case, give the case its own braces.

```javascript title="switch_scope.mjs"
function area(shape, size) {
  switch (shape) {
    case "square": {
      const side = size;
      return side * side;
    }
    case "circle": {
      const radius = size;
      return Math.round(Math.PI * radius ** 2);
    }
    default:
      throw new Error(`unknown shape: ${shape}`);
  }
}

console.log(area("square", 3), area("circle", 2));
```

```text
9 13
```

Without the braces, two cases that each declared `const side` would clash in one scope and be a `SyntaxError`.

When the branches test different conditions, or use ranges, an `if` chain is the better fit. Many `switch` statements are better replaced by an object that maps the value to a result, which a later module covers.

## Short-circuit operators

In JavaScript `&&` and `||` do not return `true` or `false`. They return **one of their operands**.

- `a && b` returns `a` if `a` is falsy, otherwise `b`.
- `a || b` returns `a` if `a` is truthy, otherwise `b`.

They also **short-circuit**: the right side is not evaluated when the left side already decides the result.

```javascript title="short_circuit.mjs"
const user = { name: "Ada", admin: false };

console.log(user.name && user.name.toUpperCase());
console.log("" && "never reached");
console.log(user.nickname || user.name);
console.log(0 || "" || null);
console.log(1 && 2 && 3);

user.admin && console.log("admin tools");
user.admin || console.log("not an admin");
```

```text
ADA

Ada
null
3
not an admin
```

The first line is the guard idiom: only call `toUpperCase` when `user.name` is there. The second prints an empty line, which is the empty string that `&&` returned. `||` returns the first truthy operand, or the last operand when none is truthy: `0 || "" || null` is `null`.

The last two lines use short-circuiting as a statement. It works, but an `if` is clearer, and linters often flag it. Use `&&` and `||` for values, and `if` for actions. For defaults, remember from the [lesson on null, undefined and nullish operators](../null-undefined-nullish/) that `??` is usually safer than `||`.

## Common pitfalls

- **A missing `break`.** Each `case` falls into the next one. Add `break` or `return`, or leave a comment where fall-through is deliberate.
- **Assignment instead of comparison.** `if (x = 5)` assigns and is always truthy. Use `===`.
- **Testing truthiness when `0` or `""` are valid.** Compare explicitly.
- **Nested `? :` chains that nobody can read.** Switch to `if` or a lookup.
- **Expecting `switch` to match across types.** It uses `===`, so `"5"` and `5` are different cases.

## Exercises

<Exercise title="Leap year checker">

A year is a leap year if it is divisible by 4, except years divisible by 100, unless they are also divisible by 400. Write `isLeapYear(year)` and test it on 1900, 2000, 2023 and 2024.

<Solution>

```javascript title="leap_year.mjs"
function isLeapYear(year) {
  if (year % 400 === 0) return true;
  if (year % 100 === 0) return false;
  return year % 4 === 0;
}

for (const year of [1900, 2000, 2023, 2024]) {
  console.log(year, isLeapYear(year));
}
```

```text
1900 false
2000 true
2023 false
2024 true
```

The tests run from the most specific rule to the least, with a guard clause per rule. 1900 passes the divisible-by-100 test and returns `false`, 2000 is caught first by the 400 rule, and 2023 and 2024 fall to the final divisible-by-4 test.

</Solution>

</Exercise>

<Exercise title="Grade calculator">

Write `grade(score)` that returns `"A"` for 90 and above, `"B"` for 80, `"C"` for 70, `"D"` for 60 and `"F"` below that. Anything that is not a number from 0 to 100 should give `"invalid"`. Test with `95, 80, 79.5, 60, 12, 101, "90", NaN`.

<Solution>

```javascript title="grade.mjs"
function grade(score) {
  if (typeof score !== "number" || Number.isNaN(score) || score < 0 || score > 100) {
    return "invalid";
  }
  if (score >= 90) return "A";
  if (score >= 80) return "B";
  if (score >= 70) return "C";
  if (score >= 60) return "D";
  return "F";
}

for (const s of [95, 80, 79.5, 60, 12, 101, "90", NaN]) {
  console.log(s, grade(s));
}
```

```text
95 A
80 B
79.5 C
60 D
12 F
101 invalid
90 invalid
NaN invalid
```

The first guard rejects everything that is not a usable score. `NaN` has the type `"number"`, so it needs its own check. Then each later line only needs a lower bound, because the higher scores have already returned. The string `"90"` is rejected on purpose: converting input to a number is a separate step.

</Solution>

</Exercise>

## Summary

- Use `if`, `else if` and `else` with blocks. Conditions use truthiness, so compare explicitly when `0` or `""` are valid values.
- Guard clauses handle the special cases first and keep the main path flat.
- `condition ? a : b` chooses a value. Keep it short.
- `switch` uses `===`, falls through until `break` or `return`, and shares one scope between cases.
- `&&` and `||` return an operand, not a boolean, and stop early.
