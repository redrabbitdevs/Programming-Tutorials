Loops repeat work. The idea and the common patterns are in the [fundamentals lesson on loops](../../../fundamentals/beginner/loops/). JavaScript has several loop forms. In practice you choose between four of them, and this lesson shows when.

## The classic for loop

A `for` loop has three parts in its brackets: an initialiser, a condition checked before each pass, and an update run after each pass.

```javascript title="for_loop.mjs"
for (let i = 0; i < 3; i++) {
  console.log("i is", i);
}

for (let i = 10; i > 0; i -= 4) {
  console.log("countdown", i);
}

let sum = 0;
for (let i = 1, j = 10; i < j; i++, j--) {
  sum += i * j;
}
console.log(sum);
```

```text
i is 0
i is 1
i is 2
countdown 10
countdown 6
countdown 2
110
```

Declare the counter with `let`. Each pass gets its own copy, as the previous lesson showed, and the counter does not exist after the loop. Any of the three parts can be a longer expression, as the last loop shows with two counters moving towards each other. It adds `1*10`, `2*9`, `3*8`, `4*7` and `5*6`, which is 110.

Use a classic `for` when you need the index or an unusual step. For plain "every item" loops, `for...of` is shorter and cannot go wrong at the ends.

## while and do...while

`while` checks its condition before each pass, so it may run zero times. Use it when you do not know in advance how many passes you need.

`do...while` checks after the pass, so the body always runs at least once.

```javascript title="while_loops.mjs"
let n = 27;
let steps = 0;

while (n !== 1) {
  n = n % 2 === 0 ? n / 2 : 3 * n + 1;
  steps++;
}

console.log("steps:", steps);
```

```text
steps: 111
```

This loop follows the Collatz sequence from 27: halve an even number, otherwise triple it and add one. It counts 111 steps to reach 1. The number of passes is not known in advance, which is why `while` fits.

`do...while` always runs its body once:

```javascript title="do_while.mjs"
let attempts = 0;
do {
  attempts++;
  console.log("attempt", attempts);
} while (attempts < 3);

let neverRuns = 0;
do {
  neverRuns++;
} while (false);
console.log(neverRuns);
```

```text
attempt 1
attempt 2
attempt 3
1
```

The second `do...while` has a condition that is always false, yet its body ran once, so `neverRuns` ends as `1`.

Every `while` needs something inside that eventually makes the condition false. A condition that never changes is an infinite loop. In a terminal, press `Ctrl+C` to stop it.

## for...of

`for...of` takes each value from an **iterable**. Arrays (ordered lists written in square brackets, covered in the [arrays lesson](../arrays-js/)) and strings are iterable, and so are maps and sets, which come later.

```javascript title="for_of.mjs"
const colours = ["red", "green", "blue"];
for (const colour of colours) {
  console.log(colour);
}

for (const char of "héllo") {
  console.log(char);
}
```

```text
red
green
blue
h
é
l
l
o
```

- Over an array you get the values, in order.
- Over a string you get one character at a time. It steps by code point, so a character outside the basic range, such as an emoji, comes through as one item even though it counts as two in `length`. The [strings lesson](../strings-js/) explains why.
- A plain object is **not** iterable. Writing `for (const x of { a: 1 })` stops with `TypeError: {(intermediate value)} is not iterable`. To loop over an object, use `for...in` below, or `Object.keys`.

Write the loop variable as `const` unless you assign to it inside the body. A new one is created for each pass.

<Callout type="note">

Arrays also have a `forEach` method that visits every item by calling a function you give it. Functions as values are covered in the [higher-order functions lesson](../higher-order-functions/). The catch is that `forEach` cannot be stopped with `break` or `continue`. If you might leave early, use `for...of`.

</Callout>

## for...in

`for...in` visits the **property names** of an object, as strings.

```javascript title="for_in.mjs"
const point = { x: 3, y: 4 };

for (const key in point) {
  console.log(key, point[key]);
}
```

```text
x 3
y 4
```

`point[key]` reads the property whose name is stored in `key`. A plain `point.key` would look for a property literally called `key`.

It has two traps. On an array it gives the indexes as **strings** (`"0"`, `"1"`), not numbers and not the values. And it also visits properties the object **inherits**, which surprises people once they use prototypes, an intermediate topic.

So use `for...of` for arrays. For an object's own keys, loop over `Object.keys(point)` with `for...of`. Reach for `for...in` only if you specifically want inherited enumerable properties.

## break, continue and labels

`break` leaves the loop immediately. `continue` skips the rest of the current pass and moves on to the next.

```javascript title="break_continue.mjs"
for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) continue;
  if (i > 7) break;
  console.log(i);
}
```

```text
1
3
5
7
```

The loop skips even numbers with `continue` and stops at the first number above 7 with `break`.

Inside nested loops a plain `break` leaves only the inner loop. A **label** names a loop so that `break` or `continue` can target an outer one.

```javascript title="break_label.mjs"
const grid = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];
let found = null;

search: for (const row of grid) {
  for (const value of row) {
    if (value * value > 20) {
      found = value;
      break search;
    }
  }
}

console.log("first value whose square exceeds 20:", found);
```

```text
first value whose square exceeds 20: 5
```

The program looks through the grid, and as soon as a value has a square above 20, it remembers that value and leaves both loops. Labels are rare. A function that returns early is often a cleaner way to leave nested loops.

## Choosing a loop

| You want to... | Use |
|---|---|
| visit every item of an array or string | `for...of` |
| count, or need the index or a custom step | classic `for` |
| repeat until a condition changes, with unknown length | `while` |
| run the body once before testing | `do...while` |
| walk an object's own keys | `for...of` with `Object.keys`, or `for...in` |

## Common pitfalls

- **Off-by-one errors.** `i <= array.length` runs one pass too many and reads `undefined`. The usual bound is `i < array.length`.
- **Using `for...in` on arrays.** You get string indexes and possibly extra properties. Use `for...of`.
- **Changing an array while looping over it.** Adding or removing items shifts the positions of the others. Loop over a copy, or build a new array.
- **Floating-point counters.** `for (let x = 0; x !== 1; x += 0.1)` never ends, because `x` never lands exactly on `1`. Count with integers and divide.
- **A `while` condition that never changes.** Check that the body moves towards the exit.

## Exercises

<Exercise title="Number-guessing game">

Write a loop that plays a guessing game against a fixed secret number (37). Give it a list of guesses, `[50, 25, 37, 10]`. For each guess, print whether it is too high, too low or right, and stop when it is right. The guess after the correct one must not be tried.

Input: none. Expected output: `Guess 1: 50 is too high`, `Guess 2: 25 is too low`, `Guess 3: 37 is right`.

<Solution>

```javascript title="guessing_game.mjs"
const secret = 37;
const guesses = [50, 25, 37, 10];

let tries = 0;
for (const guess of guesses) {
  tries++;
  if (guess === secret) {
    console.log(`Guess ${tries}: ${guess} is right`);
    break;
  }
  const hint = guess < secret ? "low" : "high";
  console.log(`Guess ${tries}: ${guess} is too ${hint}`);
}
```

```text
Guess 1: 50 is too high
Guess 2: 25 is too low
Guess 3: 37 is right
```

`for...of` walks the guesses, `tries` counts them, and `break` leaves the loop when the guess is right, so `10` is never tried. The conditional operator picks "low" or "high" inside the template literal.

</Solution>

</Exercise>

<Exercise title="Multiplication table">

Print a 5 by 5 multiplication table with the numbers lined up in columns four characters wide. Use nested loops and `padStart` from the strings lesson.

Input: none. Expected output: five lines, starting `   1   2   3   4   5` and ending `   5  10  15  20  25`.

<Solution>

```javascript title="times_table.mjs"
const size = 5;
for (let row = 1; row <= size; row++) {
  let line = "";
  for (let col = 1; col <= size; col++) {
    line += String(row * col).padStart(4);
  }
  console.log(line);
}
```

```text
   1   2   3   4   5
   2   4   6   8  10
   3   6   9  12  15
   4   8  12  16  20
   5  10  15  20  25
```

The outer loop picks the row and the inner loop builds one line, one cell at a time. `String(row * col)` turns the number into text, and `padStart(4)` pads it with spaces on the left to width 4. Each line is printed once its inner loop is done.

</Solution>

</Exercise>

<Exercise title="FizzBuzz up to 15">

Loop from 1 to 15. Print `Fizz` for multiples of 3, `Buzz` for multiples of 5, `FizzBuzz` for multiples of both, and the number itself otherwise.

Input: none. Expected output: 15 lines, starting `1`, `2`, `Fizz`, `4`, `Buzz` and ending with `FizzBuzz` for 15.

<Solution>

```javascript title="fizzbuzz.mjs"
for (let i = 1; i <= 15; i++) {
  if (i % 15 === 0) {
    console.log("FizzBuzz");
  } else if (i % 3 === 0) {
    console.log("Fizz");
  } else if (i % 5 === 0) {
    console.log("Buzz");
  } else {
    console.log(i);
  }
}
```

```text
1
2
Fizz
4
Buzz
Fizz
7
8
Fizz
Buzz
11
Fizz
13
14
FizzBuzz
```

The test for 15 goes first, because a multiple of 15 would otherwise be caught by the test for 3. The order of an `else if` chain matters.

</Solution>

</Exercise>

<Exercise title="Add up to 100 with while">

Use a `while` loop to add the numbers from 1 to 100 and print the total.

Input: none. Expected output: `5050`.

<Solution>

```javascript title="sum_to_100.mjs"
let number = 1;
let total = 0;

while (number <= 100) {
  total += number;
  number++;
}

console.log(total);
```

```text
5050
```

`number++` is what moves the loop towards its end. Without it the condition would stay true forever.

</Solution>

</Exercise>

## Summary

- Use `for...of` to visit the items of arrays and strings. Use a classic `for` when you need the index or a special step, and `while` when the number of passes is not known.
- `do...while` always runs the body once.
- `for...in` gives property names as strings. Do not use it on arrays.
- `break` leaves a loop, `continue` skips to the next pass, and a label lets either one target an outer loop.
