A variable is a name for a value. What a variable is, and how assignment differs from comparison, is covered in the [fundamentals lesson on variables and assignment](../../../fundamentals/beginner/variables-and-assignment/). This lesson covers the three ways JavaScript lets you declare one and the scope rules that come with each.

## const and let

Modern JavaScript has two declarations you should use, `const` and `let`. Both arrived in ES2015.

- `const` creates a name that cannot be assigned again.
- `let` creates a name that can.

```javascript title="let_const_basics.mjs"
let score = 10;
score = score + 5;
console.log(score);

const limit = 100;
console.log(limit);
```

```text
15
100
```

`score` changes, so it is a `let`. `limit` never changes, so it is a `const`. Assigning to a `const` stops the program:

```javascript
const limit = 100;
limit = 200;
```

```text
TypeError: Assignment to constant variable.
```

Lesson 15 shows how to catch an error like this one instead of letting it stop the program.

The next example shows that **`const` does not make a value unchangeable**. It fixes the binding between the name and the value. If the value is an array (a list) or an object (a record), you can still change what is inside it. `push` adds an item to the end of a list, and `config.retries = 5` replaces one part of a record.

```javascript title="const_contents.mjs"
const scores = [10, 20];
scores.push(30);
console.log(scores);

const config = { retries: 3 };
config.retries = 5;
console.log(config);
```

```text
[ 10, 20, 30 ]
{ retries: 5 }
```

The [lesson on copies and references](../copies-and-references/) explains why this works. For now, remember what `const` guards: the name, not the contents.

The working rule is to **start with `const`** and change to `let` only when you find the variable must be reassigned. Readers then know that every `const` keeps its meaning for the whole scope, and every `let` is a warning that the value moves.

## Updating a variable

A `let` variable is often updated from its own value. JavaScript has short forms for that. They are called **compound assignment** operators.

| Short form | Same as |
|---|---|
| `x += 3` | `x = x + 3` |
| `x -= 3` | `x = x - 3` |
| `x *= 3` | `x = x * 3` |
| `x /= 3` | `x = x / 3` |
| `x++` and `++x` | `x = x + 1` |
| `x--` and `--x` | `x = x - 1` |

`x++` and `++x` both add one, but they differ in the value they produce. The **postfix** form `x++` gives back the old value and then adds one. The **prefix** form `++x` adds one and gives back the new value. The same holds for `--`.

```javascript title="update_operators.mjs"
let count = 5;
count += 3;
count *= 2;
console.log(count);

let n = 1;
console.log(n++, n);
console.log(++n, n);
```

```text
16
1 2
3 3
```

`count` goes from 5 to 8 and then to 16. In the last two lines, `n++` prints the old value 1 and `n` becomes 2. Then `++n` makes `n` 3 and prints 3. When you use `++` on a line of its own, the two forms do the same thing. Avoid mixing them into larger expressions, because they are hard to read.

## Block scope

A **block** is the code between `{` and `}`. A bare pair of braces is a block, and so are the bodies of the `if` statements, loops and functions that the next lessons cover. Variables declared with `let` and `const` exist only inside the block where they are declared.

```javascript title="block_scope.mjs"
const outer = "outside";

{
  let inner = "inside";
  const alsoInner = 42;
  var leaky = "var ignores blocks";
  console.log(outer, inner, alsoInner);
}

console.log(leaky);
console.log(typeof inner);
```

```text
outside inside 42
var ignores blocks
undefined
```

`inner` and `alsoInner` are visible inside the braces and nowhere else. `typeof inner` outside the block gives `"undefined"` because no such name exists there. (Using `typeof` on a name that was never declared does not throw. Names in the temporal dead zone, described below, are the exception.)

The `var` line behaves differently, and the output shows it: `leaky` is still available after the block. We come back to that below.

A block can also **shadow** a name from outside it:

```javascript title="shadowing.mjs"
let name = "outer name";

{
  let name = "inner name";
  console.log(name);
}

console.log(name);
```

```text
inner name
outer name
```

Declaring `name` again inside the braces creates a new, separate variable that hides the outer one until the block ends. Shadowing is legal, and it is also a common source of confusion. Prefer a different name when the two variables could be mixed up.

The scope rules in general, including lifetime, are in the [fundamentals lesson on scope and lifetime](../../../fundamentals/beginner/scope-and-lifetime/). The scope of functions gets its own lesson in the next module.

## The temporal dead zone

You cannot use a `let` or `const` variable before its declaration line runs. The span between the start of the scope and that line is the **temporal dead zone**, and touching the variable there throws a `ReferenceError`.

```javascript
console.log(later);
let later = "now it exists";
```

```text
ReferenceError: Cannot access 'later' before initialization
```

The message is the one to remember: "Cannot access 'later' before initialization". It tells you the name exists in this scope but has no value yet. That is a bug you want to find early, and the dead zone turns it into an immediate error instead of a quiet `undefined`. Even `typeof later` throws in this zone, so `typeof` is only safe for names that were never declared at all.

## var and hoisting

Before ES2015 the only declaration was `var`. It still works, and you will meet it in older code. It has differences that cause bugs.

1. **`var` is scoped to the whole function, not the block.** A `var` inside braces is visible after them, as `leaky` showed above.
2. **`var` is hoisted and starts as `undefined`.** The declaration is treated as if it were at the top of its scope, so reading it early gives `undefined` instead of an error.
3. **`var` allows the same name twice in one scope.** A second `var greeting` does not complain, which hides typos.

```javascript title="var_hoisting.mjs"
console.log(count);
var count = 5;
console.log(count);

var greeting = "hello";
var greeting = "hello again";
console.log(greeting);
```

```text
undefined
5
hello again
```

`count` is `undefined` on the first line, not an error. The second `var greeting` silently replaces the first. With `let` or `const`, that second declaration would be a `SyntaxError`.

`var` has one more trap, in loops: a `var` loop counter is shared by every pass, while a `let` counter is new on each pass. The [loops lesson](../loops-js/) and the [lesson on closures](../scope-closures/) show where that matters.

Use `let` and `const` in everything you write. Read `var` when you meet it, and replace it with `const` or `let` when you edit that code.

<Callout type="note">

At the top level of an ES module such as `.mjs`, a `var` does not become a property of the global object. Modules have their own scope. Only in a classic script does a top-level `var` become global.

</Callout>

## Common pitfalls

- **Treating `const` as "frozen".** `const` stops reassignment only. A list or record declared with `const` can still change inside.
- **Declaring with `let` out of habit.** If a variable is never reassigned, make it `const`.
- **Reading a variable above its declaration.** That is the temporal dead zone. Move the declaration up.
- **Declaring the same name twice in one scope.** `let x; let x;` is a `SyntaxError`. `var x; var x;` is allowed and hides mistakes.
- **Using a name after its block.** With `let` and `const` it is out of scope, which is usually what you want.

<Solution>


```text
2 1
```

## Summary

- Use `const` by default and `let` when a variable must be reassigned. `+=`, `-=`, `++` and `--` update a `let` variable in place.
- `let` and `const` are block-scoped. A name shadowed in an inner block hides the outer one until the block ends.
- Using a `let` or `const` before its declaration is a `ReferenceError` (the temporal dead zone).
- `var` is function-scoped, hoisted as `undefined` and may be declared twice. Treat it as legacy.
- `const` fixes the binding, not the contents of the value.
