Cryptography is the one area where you should be least creative. The algorithms are done; the bugs are in how they are used: a predictable token, a password stored so that one leak reveals it, a comparison that leaks timing, a key committed to the repository. This lesson uses only what ships with Node and browsers, and sticks to the well-trodden paths.

Two APIs are available. **Web Crypto** (`crypto.getRandomValues`, `crypto.randomUUID` and `crypto.subtle`) is a global in Node, browsers, Deno and Bun, and is asynchronous. **`node:crypto`** is Node's own module, with more algorithms and synchronous and callback forms. Everything here runs on Node 22, 24 and 26, except the `argon2` exercise.

## Random values that cannot be guessed

`Math.random()` is fast and fine for shuffling a playlist, but it is [not cryptographically secure](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math/random): its output can be predicted from earlier outputs. Anything an attacker must not guess, such as a session token, a password reset link, an API key or a one-time code, comes from a cryptographic generator:

```javascript title="cr_random.mjs"
import { randomBytes, randomInt } from "node:crypto";

// Web Crypto: the same calls work in browsers, Deno and Bun.
const id = crypto.randomUUID();
console.log("UUID v4 shape:", /^[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}$/
  .test(id));

const bytes = crypto.getRandomValues(new Uint8Array(16));
console.log("16 random bytes:", bytes.length);

// node:crypto adds conveniences on top.
const token = randomBytes(32).toString("base64url");
console.log("session token characters:", token.length);
const pin = String(randomInt(0, 1_000_000)).padStart(6, "0");
console.log("six-digit code:", /^\d{6}$/.test(pin));
```

```text
UUID v4 shape: true
16 random bytes: 16
session token characters: 43
six-digit code: true
```

Thirty-two random bytes, 256 bits, is a comfortable size for a token; `base64url` encodes it in 43 characters that are safe in URLs and cookies. `randomInt` picks uniformly; `Math.floor(bytes[0] / 256 * 10)` and similar tricks do not. `getRandomValues` fills at most 65,536 bytes per call and throws a `QuotaExceededError` above that.

## Storing passwords

Never store a password, and never store a plain hash of one. Fast hashes such as SHA-256 are designed to be cheap, so a stolen table of them can be tested against billions of guesses per second. A **password hashing function** is deliberately slow and memory-hungry, and takes a random **salt** so that two users with the same password get different hashes. `scrypt` is in `node:crypto` on every supported Node ([crypto docs](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)):

```javascript title="cr_password.mjs"
import { randomBytes, scrypt, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";

const scryptAsync = promisify(scrypt);
const COST = { N: 2 ** 15, r: 8, p: 1, maxmem: 64 * 1024 * 1024 };

// Store "scrypt$N$r$p$salt$hash" so the parameters travel with the hash.
async function hashPassword(password) {
  const salt = randomBytes(16);
  const hash = await scryptAsync(password, salt, 32, COST);
  const { N, r, p } = COST;
  return ["scrypt", N, r, p, salt.toString("base64url"),
    hash.toString("base64url")].join("$");
}
```

`N` is the cost: each doubling doubles both time and memory. scrypt needs about `128 * N * r` bytes, and Node refuses to use more than `maxmem`, 32 MiB by default, so a cost of 2<sup>15</sup> needs a higher limit. `promisify` turns the callback API into one that returns a promise; the callback form runs on Node's thread pool, so hashing does not block the event loop.

Verifying recomputes the hash with the stored salt and parameters, and compares:

```javascript title="cr_password.mjs (continued)"
async function verifyPassword(password, stored) {
  const [scheme, N, r, p, salt, hash] = stored.split("$");
  if (scheme !== "scrypt") return false;
  const expected = Buffer.from(hash, "base64url");
  const actual = await scryptAsync(password, Buffer.from(salt, "base64url"),
    expected.length, { N: +N, r: +r, p: +p, maxmem: COST.maxmem });
  return timingSafeEqual(actual, expected);
}
```

`timingSafeEqual` takes the same time however many leading bytes match. `===` on strings, or a loop that returns at the first difference, finishes sooner the more bytes are right, and over many requests that difference can be measured. It throws if the two lengths differ, which is why the length comes from the stored hash.

```javascript title="cr_password.mjs (continued)"
const stored = await hashPassword("correct horse battery staple");
console.log(stored.split("$").slice(0, 4).join("$"), "...");
console.log("right password:",
  await verifyPassword("correct horse battery staple", stored));
console.log("wrong password:", await verifyPassword("Tr0ub4dor&3", stored));
const again = await hashPassword("correct horse battery staple");
console.log("same password, same hash:", again === stored);
```

```text
scrypt$32768$8$1 ...
right password: true
wrong password: false
same password, same hash: false
```

On my machine one hash took about 100 ms, which a login can afford and an attacker with a stolen table cannot. <Since v="24.7" /> Node 24.7 added `crypto.argon2`, the winner of the Password Hashing Competition; the second exercise uses it.

## Signing: proving data was not changed

To hand a client some data, such as a session or an unsubscribe link, and accept it back later, you need to know it was not edited. An **HMAC** is a hash keyed with a secret: only someone with the key can produce the right one for a given text.

```javascript title="cr_hmac.mjs"
import { createHmac, timingSafeEqual } from "node:crypto";

// In a real app this comes from the environment, never from the code.
const key = Buffer.from("k3y-for-the-example-only-0123456789abcdef");

const mac = (text) => createHmac("sha256", key).update(text).digest();

function sign(payload) {
  const body = Buffer.from(JSON.stringify(payload)).toString("base64url");
  return `${body}.${mac(body).toString("base64url")}`;
}
```

Verification recomputes the HMAC and compares in constant time, checking the length first:

```javascript title="cr_hmac.mjs (continued)"
function verify(token) {
  const [body, signature = ""] = token.split(".");
  const given = Buffer.from(signature, "base64url");
  const expected = mac(body);
  if (given.length !== expected.length) return null;
  if (!timingSafeEqual(given, expected)) return null;
  return JSON.parse(Buffer.from(body, "base64url").toString());
}
```

The body is only encoded, not encrypted: anyone can read it. What they cannot do is change it:

```javascript title="cr_hmac.mjs (continued)"
const token = sign({ user: "ada", role: "reader" });
console.log(token);
console.log(verify(token));

// Change the role in the body and keep the old signature.
const [, signature] = token.split(".");
const forged = Buffer.from('{"user":"ada","role":"admin"}')
  .toString("base64url");
console.log(verify(`${forged}.${signature}`));
```

```text
eyJ1c2VyIjoiYWRhIiwicm9sZSI6InJlYWRlciJ9.AnwbleHR_KuIn8Z-kzhEp1b4kiDBhx4GMHPv6pG0kuU
{ user: 'ada', role: 'reader' }
null
```

This is the idea behind JSON Web Tokens. For tokens that other systems must read, use a maintained JWT library rather than your own format, and always check the algorithm and the expiry, which the first exercise adds.

## Encrypting with Web Crypto

When the data itself is secret, encrypt it. **AES-GCM** is authenticated encryption: it hides the content and also detects any change to it. The key here is created in memory; `false` makes it non-extractable, so the raw key bytes can never be read back out of it.

```javascript title="cr_subtle.mjs"
// AES-GCM with Web Crypto: runs unchanged in Node and in browsers.
const key = await crypto.subtle.generateKey(
  { name: "AES-GCM", length: 256 }, false, ["encrypt", "decrypt"]);

async function encrypt(text) {
  // A fresh 12-byte IV for every message: never reuse one with a key.
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const data = new TextEncoder().encode(text);
  const sealed = await crypto.subtle.encrypt(
    { name: "AES-GCM", iv }, key, data);
  return { iv, sealed: new Uint8Array(sealed) };
}
```

Decryption needs the same key and IV. The IV is not secret, so store it next to the ciphertext:

```javascript title="cr_subtle.mjs (continued)"
async function decrypt({ iv, sealed }) {
  const data = await crypto.subtle.decrypt(
    { name: "AES-GCM", iv }, key, sealed);
  return new TextDecoder().decode(data);
}

const message = await encrypt("meet at noon");
console.log("ciphertext + tag bytes:", message.sealed.length);
console.log(await decrypt(message));

message.sealed[0] ^= 1; // flip one bit
try {
  await decrypt(message);
} catch (error) {
  console.log("tampered:", error.name);
}
```

```text
ciphertext + tag bytes: 28
meet at noon
tampered: OperationError
```

Twelve bytes of text became 28: the same 12 bytes encrypted, plus a 16-byte authentication tag. Flipping a single bit makes decryption fail instead of returning garbage. Reusing an IV with the same key breaks GCM badly, which is why the IV is random and fresh for every message.

## Keeping secrets out of the code

Keys, database passwords and API tokens do not belong in source files, where they end up in every clone, every fork and the history forever. Read them from the environment, check at startup that they are there, and never print them:

```javascript title="cr_config.mjs"
// Read secrets from the environment, fail fast if one is missing, and
// never print them.
function required(name) {
  const value = process.env[name];
  if (!value) throw new Error(`missing environment variable ${name}`);
  return value;
}

const config = {
  databaseUrl: required("DATABASE_URL"),
  apiKey: required("PAYMENTS_API_KEY"),
};
const mask = (s) => `${s.slice(0, 4)}... (${s.length} characters)`;
console.log("database:", new URL(config.databaseUrl).host);
console.log("payments key:", mask(config.apiKey));
```

In development, a file of test values loaded with [`--env-file`](../../intermediate/node-runtime/#env-files-and-env-file) stands in for the real environment; keep such files out of version control with `.gitignore`:

```text frame="terminal"
$ node --env-file=cr_dev.env cr_config.mjs
database: localhost:5432
payments key: test... (29 characters)
$ node cr_config.mjs

                    ^
```

In production, the platform's secret store (your CI's secrets, a cloud secret manager, an orchestrator's secrets) sets the variables. Environment variables are inherited by every child process, so pass a child only the variables it needs with the `env` option of `spawn`. If a key leaks anyway, rotate it: deleting the commit does not remove it from forks and caches.

## Common pitfalls

- **`Math.random` for anything secret.** Use `crypto.randomUUID`, `getRandomValues`, `randomBytes` or `randomInt`.
- **Fast hashes for passwords.** SHA-256, even salted, is far too cheap. Use scrypt or argon2 with a random salt.
- **Comparing secrets with `===`.** Use `timingSafeEqual` on equal-length buffers.
- **Reusing an AES-GCM IV,** or deriving it from a counter you might reset. Generate 12 random bytes per message.
- **Logging configuration objects.** One `console.log(config)` puts every secret in your logs.

## Exercises

<Exercise title="Tokens that expire">

Extend the HMAC token with an `exp` claim, seconds since the epoch. `issue(claims, { now, ttl })` adds `exp: now + ttl`; `check(token, { now })` returns the claims, or `"malformed"`, `"bad signature"` or `"expired"`. Use a fixed clock, `now = 1_800_000_000`, and a 900-second lifetime. Expected: checking after 60 seconds prints `{ user: 'ada', exp: 1800000900 }`, after 901 seconds `expired`, a body with a later `exp` and the old signature `bad signature`, and `"not-a-token"` gives `malformed`.

<Solution>

```javascript title="cr_ex_token.mjs"
import { createHmac, timingSafeEqual } from "node:crypto";

const key = Buffer.from("another-example-key-never-hard-code-me");
const mac = (text) => createHmac("sha256", key).update(text).digest();
const b64 = (text) => Buffer.from(text).toString("base64url");

// A token that carries its own expiry time, in seconds since the epoch.
function issue(claims, { now, ttl }) {
  const body = b64(JSON.stringify({ ...claims, exp: now + ttl }));
  return `${body}.${mac(body).toString("base64url")}`;
}

// The claims, or a reason why the token is not acceptable.
function check(token, { now }) {
  const parts = token.split(".");
  if (parts.length !== 2) return "malformed";
  const [body, signature] = parts;
  const given = Buffer.from(signature, "base64url");
  const expected = mac(body);
  if (given.length !== expected.length || !timingSafeEqual(given, expected)) {
    return "bad signature";
  }
  const claims = JSON.parse(Buffer.from(body, "base64url").toString());
  return claims.exp > now ? claims : "expired";
}

const now = 1_800_000_000; // a fixed clock keeps the output stable
const token = issue({ user: "ada" }, { now, ttl: 900 });
console.log(check(token, { now: now + 60 }));
console.log(check(token, { now: now + 901 }));
const longer = b64(JSON.stringify({ user: "ada", exp: now + 99_999 }));
console.log(check(`${longer}.${token.split(".")[1]}`, { now }));
console.log(check("not-a-token", { now }));
```

```text
{ user: 'ada', exp: 1800000900 }
expired
bad signature
malformed
```

The signature is checked before the body is parsed, so `JSON.parse` never sees attacker-controlled text that was not signed by you. In the app, pass `now: Math.floor(Date.now() / 1000)`.

</Solution>

</Exercise>

<Exercise title="Passwords with argon2">

<Since v="24.7" /> Rewrite the password functions with `crypto.argon2` and the `argon2id` variant: a 16-byte random nonce (argon2's name for the salt), `parallelism: 1`, `memory: 65536` (in KiB), `passes: 3` and a 32-byte tag, stored as `argon2id$nonce$tag`. Expected: `parts: 3`, `right: true` and `wrong: false`.

<Solution>

```javascript title="cr_ex_argon2.mjs"
import { argon2, randomBytes, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";

const argon2Async = promisify(argon2);
// 64 MiB of memory and 3 passes, as in the example in Node's crypto docs.
const PARAMS = { parallelism: 1, memory: 65536, passes: 3, tagLength: 32 };

async function hashPassword(password) {
  const nonce = randomBytes(16);
  const tag = await argon2Async("argon2id",
    { ...PARAMS, message: password, nonce });
  return `argon2id$${nonce.toString("base64url")}$${tag.toString("base64url")}`;
}

async function verifyPassword(password, stored) {
  const [scheme, nonce, tag] = stored.split("$");
  if (scheme !== "argon2id") return false;
  const actual = await argon2Async("argon2id",
    { ...PARAMS, message: password, nonce: Buffer.from(nonce, "base64url") });
  return timingSafeEqual(actual, Buffer.from(tag, "base64url"));
}

const stored = await hashPassword("hunter2 but longer");
console.log("parts:", stored.split("$").length);
console.log("right:", await verifyPassword("hunter2 but longer", stored));
console.log("wrong:", await verifyPassword("hunter3 but longer", stored));
```

```text
parts: 3
right: true
wrong: false
```

A real format should also store the parameters, as the scrypt version does, so that they can change later. On Node 22 the import fails with a `SyntaxError`: `node:crypto` does not provide an export named `argon2` there.

</Solution>

</Exercise>

<Exercise title="Upgrade old hashes on login">

Costs should rise as hardware gets faster, but you cannot rehash passwords you do not know. Store scrypt hashes as `scrypt$N$salt$hash`, and make `login(users, name, password)` verify the password and, when it is right and the stored `N` is below the current 2<sup>15</sup>, replace the stored hash with a new one. Start with a user hashed at 2<sup>12</sup>. Expected: `stored cost: 4096`, `wrong password: false 4096`, `right password: true 32768` and `still works: true`.

<Solution>

```javascript title="cr_ex_rehash.mjs"
import { randomBytes, scrypt, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";

const scryptAsync = promisify(scrypt);
const MAXMEM = 128 * 1024 * 1024;
const CURRENT_N = 2 ** 15;

async function hashPassword(password, N = CURRENT_N) {
  const salt = randomBytes(16);
  const hash = await scryptAsync(password, salt, 32, { N, maxmem: MAXMEM });
  return `scrypt$${N}$${salt.toString("base64url")}$${hash.toString("base64url")}`;
}

// Verify, and say whether the stored hash uses an outdated cost.
async function verify(password, stored) {
  const [, n, salt, hash] = stored.split("$");
  const expected = Buffer.from(hash, "base64url");
  const actual = await scryptAsync(password, Buffer.from(salt, "base64url"),
    expected.length, { N: Number(n), maxmem: MAXMEM });
  return { ok: timingSafeEqual(actual, expected), stale: Number(n) < CURRENT_N };
}

// On a successful login, upgrade an outdated hash in place.
async function login(users, name, password) {
  const result = await verify(password, users.get(name));
  if (result.ok && result.stale) {
    users.set(name, await hashPassword(password));
  }
  return result.ok;
}

const users = new Map([["ada", await hashPassword("pa55-phrase", 2 ** 12)]]);
const cost = () => users.get("ada").split("$")[1];
console.log("stored cost:", cost());
console.log("wrong password:", await login(users, "ada", "nope"), cost());
console.log("right password:", await login(users, "ada", "pa55-phrase"), cost());
console.log("still works:", await login(users, "ada", "pa55-phrase"));
```

```text
stored cost: 4096
wrong password: false 4096
right password: true 32768
still works: true
```

A failed login never upgrades the hash: only the right password can produce the new one.

</Solution>

</Exercise>

## Summary

- Secrets come from `crypto.randomUUID`, `getRandomValues`, `randomBytes` or `randomInt`, never `Math.random`.
- Store passwords with scrypt (or <Since v="24.7" /> argon2), a random 16-byte salt and stored parameters; compare with `timingSafeEqual`.
- HMAC signs data so that changes are detected; the content stays readable.
- AES-GCM through `crypto.subtle` encrypts and authenticates; use a fresh random 12-byte IV per message.
- Keep secrets in the environment, check them at startup, mask them in output, and rotate any that leak.
