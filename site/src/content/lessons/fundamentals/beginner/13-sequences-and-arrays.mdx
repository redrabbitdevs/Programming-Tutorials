Until now every variable has held one value. Real programs hold many: the scores in a game, the lines of a file, the pixels in an image. You could not write `score1`, `score2`, `score3` forever, so languages give you a **sequence**: one name that stands for an ordered collection of values, with each value reachable by its position.

## Index: a number for each position

In a sequence every element has an **index**, its distance from the start. Counting starts at **0**, so a sequence of four elements has indexes 0, 1, 2 and 3. The reason is arithmetic rather than whim: the index is an offset from the first element, and the first element is zero steps away.

```text
index:     0    1    2    3
value:   [10 | 20 | 30 | 40]
```

The **length** is the number of elements (4), and the last valid index is always `length - 1`. Asking for index 4 here is an error, or worse (see the pitfalls). This is the same off-by-one care you took in the [loops lesson](../loops/).

Notes on the differences:

- A **slice** takes a range of positions. In all these languages the start is included and the end is excluded, so `[1:3]` means indexes 1 and 2. C has no slice operation; you work with the same elements directly (or copy them with `memcpy`).
- C does not remember an array's length, so the program computes it once (`sizeof scores / sizeof scores[0]` is total bytes divided by bytes per element). Python, JavaScript and Java arrays know their own length.
- Java and C arrays hold one type only (`int` here). Python and JavaScript lists can mix types, though keeping them uniform is a good habit.

## Arrays and dynamic arrays

A true **array** is a block of memory big enough for a fixed number of elements, all side by side. Because every element has the same size, the computer finds element `i` by simple arithmetic (start address plus `i` times the element size), which makes reading by index fast whatever the length. The price is that the size is fixed when the array is created. Java's `int[]` and C's `int[]` are arrays in this sense.

Most of the time you do not know in advance how many items you will have. A **dynamic array** (a *list* in Python, an *array* in JavaScript, `ArrayList` in Java) solves this by keeping a true array inside and replacing it with a bigger one, copying the elements across, when it fills up. You get the convenience of "add to the end" and still have fast access by index. Python and JavaScript use dynamic arrays as their everyday sequence, so you will rarely meet a fixed-size array there. C has no built-in dynamic array; programs allocate and grow one by hand, which a later lesson covers.

The common operations, and their usual cost:

| Operation | Python | JavaScript | Java (`ArrayList`) | C (fixed array) | Cost |
|---|---|---|---|---|---|
| Read or write by index | `a[i]`, `a[i] = x` | `a[i]`, `a[i] = x` | `a.get(i)`, `a.set(i, x)` | `a[i]`, `a[i] = x` | fast, independent of length |
| Add to the end | `a.append(x)` | `a.push(x)` | `a.add(x)` | not possible: size is fixed | fast on average |
| Insert or remove in the middle or at the front | `a.insert(i, x)`, `a.pop(i)` | `a.splice(i, 0, x)`, `a.splice(i, 1)` | `a.add(i, x)`, `a.remove(i)` | shift elements by hand | slower: later elements must shift |
| Search for a value | `x in a` | `a.includes(x)` | `a.contains(x)` | loop over the elements | looks at elements one by one |

A later lesson on Big-O makes "fast" and "slower" precise. For now, remember that shifting elements is the expensive part.

## Mutation: in place or a new sequence?

A sequence is usually **mutable**: you can change it after creating it. The important question for every operation is whether it changes the sequence **in place** or returns a **new** one. Mixing the two up causes some of the most common beginner bugs. Start with sorting. Each program adds 4 to `[3, 1, 2]`, sorts it in place, then builds a separate sorted copy of `[3, 1, 2]`.

<Tabs>
<Tab label="Python">

```python title="seq_demo.py"
nums = [3, 1, 2]

nums.append(4)           # in place: nums is now [3, 1, 2, 4]
nums.sort()              # in place: returns None, not the list
print(nums)

ordered = sorted([3, 1, 2])  # builds a new list; the original is untouched
print(ordered)
```

</Tab>
<Tab label="JavaScript">

```javascript title="seq_demo.js"
const nums = [3, 1, 2];

nums.push(4);                        // in place: nums is now [3, 1, 2, 4]
nums.sort((a, b) => a - b);          // in place
console.log(`[${nums.join(", ")}]`);

const ordered = [3, 1, 2].toSorted((a, b) => a - b);  // builds a new array (ES2023)
console.log(`[${ordered.join(", ")}]`);
```

JavaScript's `sort` compares items as text unless you pass a comparison function, so `[10, 9, 1].sort()` gives `[1, 10, 9]`. The `(a, b) => a - b` makes it compare numbers.

<Tab label="C">

```c title="seq_demo.c"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static int compare(const void *a, const void *b) {
    return *(const int *)a - *(const int *)b;
}

static void print_array(const int *items, int count) {
    printf("[");
    for (int i = 0; i < count; i++) {
        printf("%s%d", i > 0 ? ", " : "", items[i]);
    }
    printf("]\n");
}

int main(void) {
    int nums[] = {3, 1, 2, 4};       /* a C array cannot grow, so 4 is already included */
    qsort(nums, 4, sizeof nums[0], compare);   /* in place */
    print_array(nums, 4);

    int original[] = {3, 1, 2};
    int ordered[3];
    memcpy(ordered, original, sizeof original);   /* copy first, then sort the copy */
    qsort(ordered, 3, sizeof ordered[0], compare);
    print_array(ordered, 3);
    return 0;
}
```

C's `qsort` always sorts in place, so a sorted copy means copying first.

## Common pitfalls

- **Off-by-one errors.** The valid indexes are `0` to `length - 1`. Looping to `length + 1` goes one too far.
- **Out-of-range access.** Python raises `IndexError`, Java raises `ArrayIndexOutOfBoundsException`, JavaScript quietly gives `undefined`, and C reads or writes whatever memory happens to be there. The C behaviour is undefined, can corrupt other data, and is a classic source of security bugs.
- **Changing a list while looping over it.** Removing items during iteration makes the loop skip elements. Build a new list instead.
- **Assuming a sort returns the sorted list.** In Python it returns `None`; in JavaScript it returns the same array.
- **Thinking a copy is a copy.** `b = a` does not copy the list; both names refer to the same one. This gets a full lesson in [memory and references](../memory-and-references/).

<Exercise title="Reverse in place">

Write `reverse_in_place(items)` that reverses a list without building a second list. Hint: swap the first and last elements, then the second and second-to-last, and stop in the middle. Test it on `[1, 2, 3, 4, 5]` (expected `[5, 4, 3, 2, 1]`) and `[1, 2, 3, 4]` (expected `[4, 3, 2, 1]`).

<Solution>

Walk an index `i` from the start and swap `items[i]` with its mirror `items[n - 1 - i]`. Only the first half needs visiting: swapping the second half would undo the work.

```python title="seq_reverse.py"
def reverse_in_place(items):
    n = len(items)
    for i in range(n // 2):
        items[i], items[n - 1 - i] = items[n - 1 - i], items[i]


nums = [1, 2, 3, 4, 5]
reverse_in_place(nums)
print(nums)

evens = [1, 2, 3, 4]
reverse_in_place(evens)
print(evens)
```


<Exercise title="Rotate by k">

Write `rotate(items, k)` that returns a new list with every element moved `k` places to the left, the elements that fall off the front wrapping around to the back. Make it work when `k` is larger than the length. Test it on `rotate([1, 2, 3, 4, 5], 2)` (expected `[3, 4, 5, 1, 2]`) and `rotate([1, 2, 3, 4, 5], 7)` (expected `[3, 4, 5, 1, 2]`).

<Solution>

Take everything from position `k`, then everything before it. Using `k % n` handles a `k` larger than the length (and an empty list needs a guard so we never divide by zero). Python and JavaScript can do it with slices; Java and C fill a new array element by element, where element `i` of the result is element `(i + k) % n` of the input.

<Tabs>
<Tab label="Python">

```python title="seq_rotate.py"
def rotate(items, k):
    if not items:
        return []
    k = k % len(items)
    return items[k:] + items[:k]


print(rotate([1, 2, 3, 4, 5], 2))
print(rotate([1, 2, 3, 4, 5], 7))
```

</Tab>
<Tab label="JavaScript">

```javascript title="seq_rotate.js"

  if (items.length === 0) {
    return [];
  }
  const shift = k % items.length;
  return items.slice(shift).concat(items.slice(0, shift));
}
```

## Summary

- A sequence stores values in order; an index from 0 to `length - 1` picks one out.
- Arrays have a fixed size and fast access by index. Dynamic arrays (lists) grow as needed.
- Know whether each operation changes a sequence in place or returns a new one.
