Most Python operators behave the way arithmetic class taught you. A handful do not, and those are the ones that cause bugs: `-2 ** 2`, a comparison that chains, and `and` returning something that is not a boolean.

The fundamentals lesson explains precedence and short-circuiting in general. This lesson covers how Python applies them.

## Precedence in practice

From tightest to loosest, the groups you will meet most are: `**`, unary `-`, then `*` `/` `//` `%`, then `+` `-`, then comparisons, then `not`, `and` and `or`. When in doubt, add parentheses. They cost nothing and tell the next reader what you meant.

```python title="precedence.py"
print(2 + 3 * 4)
print(-2 ** 2)
print((-2) ** 2)
print(2 ** 3 ** 2)
print(10 - 4 - 3)
print(not 1 == 2)
print(1 + 2 == 3 and 4 > 3)
```

```text
14
-4
4
512
3
True
True
```

- `-2 ** 2` is `-(2 ** 2)`, because `**` binds tighter than a unary minus on its left.
- `**` groups right to left, so `2 ** 3 ** 2` is `2 ** (3 ** 2)`, which is 512. Subtraction groups left to right: `10 - 4 - 3` is `(10 - 4) - 3`.
- `not 1 == 2` is `not (1 == 2)`, because comparisons bind tighter than `not`.

## Chained comparisons

Python lets you chain comparisons the way mathematics does. `a < b < c` means `a < b and b < c`, with `b` evaluated only once.

```python title="chained_and_or.py"
age = 25
print(18 <= age < 65)
print(1 < 3 < 2)

print(0 or "default")
print("name" or "default")
print("" and "never")
print(5 and 7)

nickname = ""
print(nickname or "anonymous")
```

```text
True
False
default
name

7
anonymous
```

## and and or return operands

`and` and `or` do not return `True` or `False`. They return one of their two operands:

- `a or b` returns `a` if `a` is truthy, otherwise `b`.
- `a and b` returns `a` if `a` is falsy, otherwise `b`.

Both stop as soon as the answer is known, which is called short-circuiting. That is why `"" and "never"` gives the empty string: the right side is never looked at (the blank line in the output is that empty string).

This makes `value or default` a popular way to supply a fallback. Be careful, though: it replaces every falsy value, including `0` and `""`, not just missing ones. The next module covers truthiness in detail.

## The walrus operator

The assignment expression `:=`, nicknamed the walrus, binds a name in the middle of an expression. It exists since Python 3.8 and is most useful for avoiding a repeated call.

```python title="walrus.py"
words = ["spam", "eggs", "bacon"]

if (count := len(words)) > 2:
    print(f"{count} words is a lot")

total = 0
while (n := total + 3) < 10:
    total = n
print(total)
```

```text
3 words is a lot
9
```

Wrap a walrus in parentheses unless it stands alone, and use it sparingly. If a plain assignment on its own line reads better, use that.

## Common pitfalls

- **`x == 1 or 2`.** This parses as `(x == 1) or 2`, which is always truthy. Write `x == 1 or x == 2`, or `x in (1, 2)`.
- **Misusing a chain.** `1 < x > 0` is legal but confusing. Keep chains in one direction.
- **Reading `a != b != c` as "all three differ".** It means `a != b and b != c`, so `a` and `c` may still be equal.
- **Using `or` for defaults when `0` is valid.** `count or 10` turns a real `0` into `10`.

## Summary

- `**` binds tighter than a unary minus, and `**` groups right to left. Use parentheses when unsure.
- `a < b < c` is a chained comparison. `and` and `or` return one of their operands.
- `:=` names a value inside an expression and has existed since Python 3.8.
