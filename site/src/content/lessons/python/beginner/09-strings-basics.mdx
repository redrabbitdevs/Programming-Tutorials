Almost every program handles text: names, messages, file contents. In Python all of that is the `str` type, and a few rules about it, such as quoting, slicing and immutability, are worth learning properly.

The fundamentals lesson on text explains characters, code points and encodings in general. Here we look at Python's syntax for strings.

## Creating strings

Single and double quotes are interchangeable, so you can pick whichever avoids a backslash. Triple quotes allow a string to span several lines.

```python title="string_basics.py"
single = 'It is'
double = "It's"
triple = """Line one
Line two"""
print(single, double)
print(triple)
print("Tab:\tdone")
print("C:\new")
print(r"C:\new")
print("ab" "cd")

word = "Python"
print(word[0], word[-1])
print(word[1:4], word[:2], word[4:])
print(word[::-1])
print(len(word), "th" in word)
print("ha" * 3 + "!")
try:
    word[0] = "J"
except TypeError as error:
    print(error)
print("J" + word[1:])
```

## Escapes and raw strings

A backslash starts an escape sequence: `\n` is a newline, `\t` a tab, `\\` a literal backslash, and `\"` a quote. That is why `"C:\new"` prints a line break in the middle of a Windows path.

Put an `r` before the opening quote to make a **raw string**, where backslashes are left alone. Raw strings are handy for Windows paths and for regular expressions.

Two string literals side by side, like `"ab" "cd"`, are joined into one at compile time. It is occasionally useful for splitting a long literal over several lines.

## Indexing and slicing

Each character has a position that starts at 0. Negative numbers count from the end, so `word[-1]` is the last character.

A slice `word[start:stop]` takes characters from `start` up to, but not including, `stop`. You can leave either end out, and add a third number for the step: `word[::-1]` reverses the string. Slices never raise an error for out-of-range ends, but an out-of-range *single index* raises `IndexError`.

The lists module teaches slicing in depth, and the same rules apply to lists and tuples.

## Strings are immutable

You cannot change a string in place. `word[0] = "J"` raises a `TypeError`. Instead, build a new string and bind your name to it, as the last line of the example does with `"J" + word[1:]`. This is the same name-and-object idea from the variables lesson.

The other basics: `len(text)` counts characters, `in` tests for a substring, `+` joins two strings, and `*` repeats one.

## Common pitfalls

- **Adding a number to a string.** `"age: " + 30` raises `TypeError`. Convert with `str(30)` or, better, use an f-string (next lesson).
- **Windows paths without a raw string.** `"C:\new"` contains a newline; `"C:\Users"` is worse, because `\U` begins a Unicode escape and is a syntax error.
- **Off-by-one in slices.** `word[1:4]` has three characters, not four.
- **Expecting methods to modify the string.** Methods such as `upper()` return a new string. The original is untouched.

<Exercise title="Palindrome checker">

Write `is_palindrome(text)` that returns `True` when the text reads the same forwards and backwards, ignoring case, spaces and punctuation. Test it on `"Racecar"`, `"A man, a plan, a canal: Panama"` and `"Python"`.

<Solution>

```python title="palindrome.py"
def is_palindrome(text):
    cleaned = "".join(ch for ch in text.casefold() if ch.isalnum())
    return cleaned == cleaned[::-1]


print(is_palindrome("Racecar"))
print(is_palindrome("A man, a plan, a canal: Panama"))
print(is_palindrome("Python"))
```

```text
True
True
False
```

The generator keeps only letters and digits (`isalnum()`) after lowercasing with `casefold()`. Then `[::-1]` reverses the cleaned text for the comparison. Functions get their own module later; for now, read `def` as "name this recipe".

## Summary

- Use any quote style, triple quotes for multi-line text, and `r"..."` to switch off escapes.
- Index from 0, count from the end with negative numbers, and slice with `[start:stop:step]`.
- Strings are immutable: operations build new strings.
