<Since v="3.10" /> A long `if`/`elif` chain that compares one value against many possibilities gets noisy. Python 3.10 added the `match` statement, called **structural pattern matching**, to say the same thing more directly (PEP 634 is the specification, PEP 636 the tutorial). It does a lot more than a `switch` in other languages, but this lesson covers the everyday core. Everything in this lesson needs Python 3.10 or later.

## Literal patterns, alternatives and guards

```python title="match_basics.py"
def describe(status):
    match status:
        case 200:
            return "ok"
        case 301 | 302:
            return "redirect"
        case 404:
            return "not found"
        case code if code >= 500:
            return f"server error {code}"
        case _:
            return "other"


for status in [200, 302, 404, 503, 418]:
    print(status, describe(status))
```

```text
200 ok
302 redirect
404 not found
503 server error 503
418 other
```

The word after `match` is the **subject**. Python tries each `case` from top to bottom and runs the block of the first pattern that fits, then leaves the whole `match`. There is no fall-through, so you never write `break`.

The patterns above:

- **Literal pattern** (`case 200`): matches when the subject equals that number, string, `True`, `False` or `None`.
- **Or-pattern** (`case 301 | 302`): matches if either alternative matches.
- **Capture pattern** (`case code`): a bare name matches *anything* and binds it to that name, here `code`.
- **Guard** (`if code >= 500`): an extra condition after the pattern. The case runs only when the pattern fits *and* the guard is truthy.
- **Wildcard** (`case _`): matches anything and binds nothing. Use it last, as the "else".

## Matching shapes

Patterns can also describe the shape of a sequence. This is where `match` pulls ahead of `if`. A text-adventure command parser is a good example, since a command is a list of words:

```python title="adventure.py"
def handle(command):
    match command.split():
        case ["quit"]:
            return "Goodbye."
        case ["look"]:
            return "You see a dusty room."
        case ["go", ("north" | "south" | "east" | "west") as direction]:
            return f"You walk {direction}."
        case ["go", _]:
            return "You cannot go that way."
        case ["take", item]:
            return f"You pick up the {item}."
        case ["take", *items] if items:
            return f"One thing at a time: {', '.join(items)}."
        case []:
            return "Say something."
        case _:
            return f"I don't understand {command!r}."


for line in ["look", "go north", "go up", "take lamp", "take a b", "", "dance", "quit"]:
    print(f"> {line}")
    print(handle(line))
```

```text
> look
You see a dusty room.
> go north
You walk north.
> go up
You cannot go that way.
> take lamp
You pick up the lamp.
> take a b
One thing at a time: a, b.
> 
Say something.
> dance
I don't understand 'dance'.
> quit
Goodbye.
```

`command.split()` turns `"go north"` into `["go", "north"]`. A sequence pattern like `["go", _]` matches a two-item list whose first item is the string `"go"`; the second can be anything. Each name in the pattern is bound as the match happens:

- `["take", item]` matches exactly two words and captures the second as `item`.
- `["take", *items]` uses a star to capture any number of remaining words as a list. The guard `if items` makes sure at least one word follows.
- `("north" | "south" | "east" | "west") as direction` matches any of four literals and also keeps the matched value under a name with `as`.
- `[]` matches an empty list, which is what `"".split()` gives.

Order matters, as in `if`/`elif`. `["go", _]` sits after the direction case, so valid directions are handled first.

## When to use match

Reach for `match` when you are branching on the *value or shape* of a single subject: command parsers, message types, status codes, small tokenisers. Keep `if`/`elif` for conditions that compare different things or involve ranges and calculations. Both are fine for a few branches, so choose whichever reads better. The pattern language goes much deeper (class patterns, mappings, nested shapes), and an advanced lesson picks that up.

## Common pitfalls

- **Treating a bare name as a constant to compare against.** `case MISSING:` does not test for equality with a variable named `MISSING`. It *captures* anything into a new name `MISSING`. To match a named constant, use a dotted name such as `Status.MISSING`, which is compared by value.
- **Putting a capture or `_` before other cases.** A pattern that matches everything makes later cases unreachable. Python refuses to compile that with a `SyntaxError`, for example "name capture 'x' makes remaining patterns unreachable".
- **Forgetting that a string subject is not a list of words.** `match "go north":` with `case ["go", _]` does not match, because strings are deliberately not treated as sequences by sequence patterns. Split the text first.
- **Using it on Python older than 3.10.** `match` is a `SyntaxError` there. Check `python --version`.
- **Expecting fall-through or a `break`.** After one case runs, the `match` is done.

## Summary

- <Since v="3.10" /> `match subject:` followed by `case pattern:` blocks runs the first case that fits; there is no fall-through.
- Literals compare by value, `|` offers alternatives, a bare name captures, `_` is the wildcard, and `if` adds a guard.
- Sequence patterns such as `["go", direction]` match by shape and bind names, which makes command parsing tidy.
