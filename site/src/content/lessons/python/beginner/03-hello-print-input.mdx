A program that cannot talk to anyone is not much use. Python has two built-in functions for conversation: `print` sends text out and `input` brings text in.

If running a file from a terminal is still new, the fundamentals lesson on tools covers the shell and working directories. Here we stay with Python's side of it.

## print

`print` writes its arguments to the screen, separated by spaces, and finishes with a newline.

```python title="print_options.py"
print("a", "b", "c")
print("a", "b", "c", sep="-")
print("loading", end="...")
print("done")
print()
print("after a blank line")
```

```text
a b c
a-b-c
loading...done

after a blank line
```

Two **keyword arguments** change the behaviour. You write them by name, after the values to print.

- `sep` is what goes between items. The default is a single space.
- `end` is what goes after the last item. The default is a newline, which is why each `print` starts on a new line. Setting `end="..."` keeps the next output on the same line.

`print()` with nothing inside prints an empty line.

## input

`input(prompt)` shows the prompt, waits for the user to type a line and press Enter, then returns what they typed.

```python title="greeting.py"
TARGET_YEAR = 2030

name = input("What is your name? ")
birth_year = int(input("Which year were you born? "))

age = TARGET_YEAR - birth_year
print(f"Hello, {name}!")
print(f"In {TARGET_YEAR} you will be {age}.")
```

Run it and type your answers:

```bash frame="terminal"
python3 greeting.py
```

```text
What is your name? Ada
Which year were you born? 1990
Hello, Ada!
In 2030 you will be 40.
```

A few things to notice:

- The text in quotes before `input` is the prompt. Put a trailing space in it so the answer does not touch the question.
- `f"Hello, {name}!"` is an **f-string**: a string where `{...}` is replaced by the value inside. A later lesson covers f-strings fully.
- `TARGET_YEAR` is in capitals because it is a constant by convention: a value that does not change while the program runs.

## input always returns text

This is the single most common beginner error. Whatever the user types, `input` gives you a `str`, even if it looks like a number. Arithmetic on the wrong type either fails or does something surprising.

```python title="input_is_text.py"
text = "1990"  # what input() would hand back
print(type(text))
print(int(text) + 1)
print(text + "1")
```

```text
<class 'str'>
1991
19901
```

`int(text)` converts the text to a whole number, so adding 1 works as arithmetic. Adding `"1"` to text just glues the characters together. And mixing the two directly, like `"1990" + 1`, raises a `TypeError`.

If the text cannot be a number, `int` raises a `ValueError`:

```text
ValueError: invalid literal for int() with base 10: 'abc'
```

Handling that gracefully needs `try` and `except`, which come in the intermediate course. For now, type sensible answers when you test. For `3.5`, use `float(...)` instead of `int(...)`.

## Common pitfalls

- **Forgetting `int()`.** `input("Age? ") + 1` fails with a `TypeError`.
- **Parentheses on print.** `print "hi"` was Python 2 and is a `SyntaxError` today. `print` is a function and needs parentheses.
- **Expecting `end=` to add a space.** It replaces the newline entirely. Write `end=" "` if you want one.

## Summary

- `print(..., sep=..., end=...)` controls spacing and line endings.
- `input()` returns a `str`. Convert with `int()` or `float()` before doing arithmetic.
- Keep a trailing space in prompts so the answer reads cleanly.
