A `while` loop waits for a condition. A `for` loop is for the other common case: *do this for each item*. In Python it works on anything iterable: a list, a string, a range of numbers, the lines of a file, and many more.

## for over a sequence

```python title="for_range.py"
for i in range(3):
    print(i)
print(list(range(2, 10, 3)))
print(list(range(5, 0, -2)))

fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit.upper())

for position, fruit in enumerate(fruits, start=1):
    print(position, fruit)

for row in range(1, 4):
    line = ""
    for col in range(1, 6):
        line += f"{row * col:3}"
    print(line)
```

```text
0
1
2
[2, 5, 8]
[5, 3, 1]
APPLE
BANANA
CHERRY
1 apple
2 banana
3 cherry
  1  2  3  4  5
  2  4  6  8 10
  3  6  9 12 15
```

`for fruit in fruits:` binds the name `fruit` to each item in turn and runs the block once per item. There is no index to manage and no condition to get wrong. Strings work too: `for ch in "abc"` visits one character at a time.

## range

`range` produces numbers on demand. It takes the same arguments as a slice:

- `range(stop)` counts from 0 up to, but **not including**, `stop`.
- `range(start, stop)` begins at `start`.
- `range(start, stop, step)` moves by `step`, which may be negative.

`range(3)` gives 0, 1, 2: three numbers, which is why it suits "do this 3 times". Wrap it in `list(...)` if you want to see the numbers, as the example does. A `range` does not build the whole list in memory, so `range(1_000_000)` is cheap.

Nested loops multiply: the inner loop runs completely for every pass of the outer one. The example prints a small multiplication table this way.

## enumerate

If you need the position as well as the item, do not write `range(len(items))`. Use `enumerate`, which yields `(position, item)` pairs. The optional `start=1` begins counting at 1, which suits numbered lists shown to people. The two names before `in` unpack each pair; the tuples lesson covers unpacking properly.

## zip

`zip` walks several iterables in step and yields one tuple per position:

```python title="zip_strict.py"
names = ["Ada", "Grace", "Alan"]
scores = [95, 88, 91]

for name, score in zip(names, scores):
    print(f"{name}: {score}")

short = [1, 2]
for a, b in zip(names, short):
    print(a, b)

try:
    for a, b in zip(names, short, strict=True):
        print(a, b)
except ValueError as error:
    print("ValueError:", error)
```

```text
Ada: 95
Grace: 88
Alan: 91
Ada 1
Grace 2
Ada 1
Grace 2
ValueError: zip() argument 2 is shorter than argument 1
```

By default `zip` stops silently at the shortest input. `Alan` simply vanishes in the second loop, with no warning. <Since v="3.10" /> Passing `strict=True` makes `zip` raise a `ValueError` instead when the lengths differ (PEP 618). Use it whenever two lists are supposed to line up, so a mismatch becomes a loud error rather than lost data. Note that the error is raised when the shorter input runs out, so the pairs before it are still processed, as the repeated `Ada 1`, `Grace 2` lines show.

## Common pitfalls

- **Off-by-one with range.** `range(1, 10)` ends at 9. To include 10, write `range(1, 11)`.
- **Changing a list while looping over it.** Adding or removing items from the list you are iterating makes the loop skip items. Loop over a copy (`for x in items[:]`) or build a new list.
- **`for i in range(len(items))` just to read items.** Loop over the items themselves, or use `enumerate` when you need positions.
- **Reusing the loop variable.** After the loop, the name still holds the last item. It does not disappear, and it can clash with a name you meant to use elsewhere.
- **Silent truncation with `zip`.** Without `strict=True`, mismatched lengths lose data without a message.
- **Expecting `range` to include the stop value.** It never does, just like slices.

<Exercise title="Multiplication table">

Print a multiplication table for 1 to 4, with row and column headings, using nested loops and aligned columns.

<Solution>

```python title="mult_table.py"
size = 4
print("   " + "".join(f"{col:4}" for col in range(1, size + 1)))
for row in range(1, size + 1):
    cells = "".join(f"{row * col:4}" for col in range(1, size + 1))
    print(f"{row:2} {cells}")
```

```text
      1   2   3   4
 1    1   2   3   4
 2    2   4   6   8
 3    3   6   9  12
 4    4   8  12  16
```

The outer `range` picks the row, and the generator expression inside `join` plays the part of the inner loop. The format spec `:4` pads each number to four characters so the columns line up.

<Exercise title="Pair two lists safely">

Write `pair_up(keys, values)` that returns strings like `"x=1"`. It must raise an error if the lists have different lengths.

<Solution>

```python title="pair_lists.py"
def pair_up(keys, values):
    pairs = []
    for key, value in zip(keys, values, strict=True):
        pairs.append(f"{key}={value}")
    return pairs


print(pair_up(["x", "y", "z"], [1, 2, 3]))
try:
    print(pair_up(["x", "y", "z"], [1, 2]))
except ValueError as error:
    print("lists differ in length:", error)
```

```text
['x=1', 'y=2', 'z=3']
lists differ in length: zip() argument 2 is shorter than argument 1
```

`strict=True` does the length check for you. It needs Python 3.10 or later.

</Solution>
</Exercise>

## Summary

- `for item in iterable:` visits each item in turn; `range(start, stop, step)` generates numbers and never includes `stop`.
- Use `enumerate` for positions and `zip` for several sequences at once.
- <Since v="3.10" /> `zip(..., strict=True)` raises `ValueError` when lengths differ.
