You have already met `break` and `continue`. This lesson pins down exactly what they do, especially with nested loops, and introduces a feature that surprises newcomers and is rare in other languages: `else` on a loop.

## break, continue and nesting

- `break` ends the **innermost** loop that contains it, and execution carries on after that loop.
- `continue` abandons the rest of the current pass of the innermost loop and moves on to the next one.

Neither affects an outer loop. Python has no labelled `break`, so to leave several loops at once you usually move the loops into a function and use `return`.

```python title="loop_else_flag.py"
words = ["tree", "river", "stone"]

found = False
for word in words:
    if word.startswith("r"):
        found = True
        break
print("flag version:", found)

for word in words:
    if word.startswith("z"):
        print("found z")
        break
else:
    print("else version: no word starts with z")

for i in range(1, 4):
    for j in range(1, 4):
        if j == 2:
            continue
        if i == 3:
            break
        print(i, j)
```

```text
flag version: True
else version: no word starts with z
1 1
1 3
2 1
2 3
```

In the nested loops, `continue` skips `j == 2` in every row. When `i` is 3, `break` stops the inner loop at its very first pass, so nothing prints for row 3, but the outer loop still finishes normally.

## The else clause on a loop

A `for` or `while` loop can have an `else` block. It runs **when the loop finishes without hitting `break`**. Read it as "no break": if the loop was cut short, `else` is skipped; if it ran out of items or its condition went false, `else` runs.

That makes it a natural fit for searches, where the interesting question is "did I find it?". The second loop above searches for a word starting with `z`. If it had found one, it would print and `break`, skipping the `else`. Since none exists, the loop ends normally and the `else` reports the failure.

The older way is a **flag**: set `found = False`, flip it to `True` before `break`, and test it afterwards, as the first loop does. Both are correct. A flag is more familiar and often easier to read. `for ... else` saves a variable but is unfamiliar to many readers, so give it a comment if your team may not know it.

## Searching in practice

```python title="first_prime.py"
def is_prime(n):
    if n < 2:
        return False
    for divisor in range(2, int(n**0.5) + 1):
        if n % divisor == 0:
            return False
    return True


def report_first_prime(numbers):
    for n in numbers:
        if is_prime(n):
            print("first prime:", n)
            break
    else:
        print("no primes in", numbers)


report_first_prime([4, 6, 9, 11, 13])
report_first_prime([4, 6, 8, 10])
```

```text
first prime: 11
no primes in [4, 6, 8, 10]
```

`is_prime` itself returns from inside its loop, which is the other way to leave a loop early. In `report_first_prime`, the `else` belongs to the `for`, not to the `if`: look at the indentation.

## Common pitfalls

- **Expecting `break` to exit every loop.** It only leaves the innermost one.
- **Misreading the `else` indentation.** An `else` lined up with `for` belongs to the loop. One lined up with `if` belongs to the `if`. Mixing them up flips the logic.
- **Thinking loop `else` means "if the loop was empty".** It runs whenever there was no `break`, including after a normal, non-empty run.
- **Putting the update after `continue` in a `while`.** The skipped update can cause an infinite loop.
- **Using `for ... else` with no `break` in the loop.** Then the `else` always runs, so it is pointless. Without a `break`, it is just ordinary code after the loop.

Using `is_prime` from above, write a function `first_prime(numbers)` that **returns** the first prime in the list, or `None` if there is none. Do it without a flag variable and without `for ... else`, then explain why a loop `else` is not needed.

```python title="first_prime_return.py"
def is_prime(n):
    if n < 2:
        return False
    for divisor in range(2, int(n**0.5) + 1):
        if n % divisor == 0:
            return False
    return True


def first_prime(numbers):
    for n in numbers:
        if is_prime(n):
            return n
    return None


print(first_prime([4, 6, 9, 11, 13]))
print(first_prime([4, 6, 8, 10]))
```

```text
11
None
```

`return` leaves the loop and the function in one move, and the line after the loop only runs when nothing matched, which is exactly what `else` would express. Inside a function, early `return` is usually the clearest search.

## Summary

- `break` leaves the innermost loop; `continue` skips to its next pass.
- A loop's `else` runs only if the loop ended without `break`, which makes it a "not found" branch for searches.
- A flag variable or an early `return` achieves the same result and may read more clearly.
