A command-line tool has two audiences. A person types it and reads the help. A shell script runs it, pipes its output into something else and checks whether it succeeded. The [intermediate project](../../intermediate/project-tested-cli/) built `spend`, a tool with flat options and a `main` that returned an exit code. This lesson adds what larger tools need: subcommands, a consistent error policy, `python -m` entry points and tests. The [stdlib tour](../../intermediate/stdlib-tour/) covered the basics of `argparse`, so they are not repeated here.

## The shape of a CLI module

The `todo` tool below keeps a task list in a JSON file. Its module has three layers: functions that do the work, a parser, and a `main` that connects them. First the storage and a single exception type for problems the user can fix:

```python title="todo/cli.py"
import argparse
import json
import sys
from pathlib import Path


class TodoError(Exception):
    """A problem the user can fix. Reported in one line, no traceback."""


def load(path):
    if not path.exists():
        return []
    return json.loads(path.read_text(encoding="utf-8"))


def save(path, tasks):
    path.write_text(json.dumps(tasks, indent=1), encoding="utf-8")
```

Each subcommand is a function that receives the parsed arguments. Results go to standard output with `print`. A handler never calls `sys.exit` and never prints an error itself: it raises `TodoError` and lets `main` decide.

```python title="todo/cli.py (continued)"
def cmd_add(args):
    tasks = load(args.file)
    tasks.append({"text": args.text, "done": False})
    save(args.file, tasks)
    print(f"added #{len(tasks)}")


def cmd_list(args):
    for number, task in enumerate(load(args.file), start=1):
        mark = "x" if task["done"] else " "
        print(f"{number:>2} [{mark}] {task['text']}")


def cmd_done(args):
    tasks = load(args.file)
    if not 1 <= args.number <= len(tasks):
        raise TodoError(f"there is no task #{args.number}")
    tasks[args.number - 1]["done"] = True
    save(args.file, tasks)
```

## Subcommands

`add_subparsers` returns an object whose `add_parser` creates one parser per subcommand, each with its own arguments and help. `set_defaults(handler=...)` stores the function to call in the parsed namespace, so dispatch needs no `if` chain:

```python title="todo/cli.py (continued)"
def build_parser():
    parser = argparse.ArgumentParser(
        prog="todo", description="Keep a small list of tasks."
    )
    parser.add_argument("--file", type=Path, default=Path("todo.json"),
                        help="where the tasks are stored")
    sub = parser.add_subparsers(dest="command", required=True)

    add = sub.add_parser("add", help="add a task")
    add.add_argument("text", help="what needs doing")
    add.set_defaults(handler=cmd_add)

    show = sub.add_parser("list", help="show all tasks")
    show.set_defaults(handler=cmd_list)

    done = sub.add_parser("done", help="mark a task as done")
    done.add_argument("number", type=int, help="the task's number")
    done.set_defaults(handler=cmd_done)
    return parser
```

Options defined on the main parser, such as `--file`, go *before* the subcommand: `todo --file work.json list`. `required=True` matters, as the debugging exercise shows.

## Exit codes and the two output streams

`main` takes the argument list as a parameter, defaulting to `None`, which makes `argparse` read `sys.argv`. It returns an integer instead of exiting, which keeps it callable from tests:

```python title="todo/cli.py (continued)"
def main(argv=None):
    args = build_parser().parse_args(argv)
    try:
        args.handler(args)
    except TodoError as error:
        print(f"todo: {error}", file=sys.stderr)
        return 1
    return 0
```

The conventions it follows are the ones every Unix tool shares:

| Exit code | Meaning | Who produces it |
|---|---|---|
| `0` | success | `main` |
| `1` | the command was valid but failed | `main`, from `TodoError` |
| `2` | the command line itself was wrong | `argparse`, by raising `SystemExit(2)` |

Normal output goes to stdout, so `todo list | grep Tag` works. Errors go to stderr, so they reach the person even when stdout is piped elsewhere, prefixed with the program name so that a long pipeline still says who complained. An unexpected exception is not caught: a traceback with exit code 1 is the right result for a bug.

To see all of this at once, a small driver runs command lines the way a shell would and prints each exit code. It sends stderr to stdout so that the output below shows both:

```python title="todo_demo.py"
import contextlib
import shlex
import sys
import tempfile

from todo.cli import main


def run(command_line):
    """Run one command line as a shell would, and show its exit code."""
    print("$", command_line)
    argv = shlex.split(command_line)[1:]
    with contextlib.redirect_stderr(sys.stdout):
        try:
            code = main(argv)
        except SystemExit as exit_request:
            code = exit_request.code
    print(f"[exit {code}]")
```

```python title="todo_demo.py (continued)"
with tempfile.TemporaryDirectory() as folder, contextlib.chdir(folder):
    run("todo add 'Write the release notes'")
    run("todo add 'Tag v1.0'")
    run("todo done 1")
    run("todo list")
    run("todo done 7")
    run("todo done one")
    run("todo")
```

```text
$ todo add 'Write the release notes'
added #1
[exit 0]
$ todo add 'Tag v1.0'
added #2
[exit 0]
$ todo done 1
[exit 0]
$ todo list
 1 [x] Write the release notes
 2 [ ] Tag v1.0
[exit 0]
$ todo done 7
todo: there is no task #7
[exit 1]
$ todo done one
usage: todo done [-h] number
todo done: error: argument number: invalid int value: 'one'
[exit 2]
$ todo
usage: todo [-h] [--file FILE] {add,list,done} ...
todo: error: the following arguments are required: command
[exit 2]
```

`todo done 1` prints nothing on success, the Unix habit for commands that change state. `type=int` turned `one` into a usage error before any handler ran.

## Running it: python -m and installed commands

A `__main__.py` file in a package makes `python -m todo` work. Keep it to three lines, so that importing `todo.cli` (in tests, say) never runs the program:

```python title="todo/__main__.py"
import sys

from .cli import main

sys.exit(main())
```

Running it prints the help that `argparse` generated from the parser:

```console
$ python -m todo --help
usage: todo [-h] [--file FILE] {add,list,done} ...

Keep a small list of tasks.

positional arguments:
  {add,list,done}
    add            add a task
    list           show all tasks
    done           mark a task as done

options:
  -h, --help       show this help message and exit
  --file FILE      where the tasks are stored
```

For an installed command, add `todo = "todo.cli:main"` under `[project.scripts]`, as in the [pyproject lesson](../../intermediate/pyproject-uv/). The generated script passes `main`'s return value to `sys.exit`, so the same exit codes come out.

## The rest of the argparse vocabulary

`todo` used positionals, `type=` and subcommands. Most other tools need a handful of further shapes, all shown in this parser for an imaginary `fetch` command:

```python title="argparse_shapes.py"
import argparse

common = argparse.ArgumentParser(add_help=False)
common.add_argument("-v", "--verbose", action="count", default=0)

parser = argparse.ArgumentParser(prog="fetch", parents=[common])
parser.add_argument("--version", action="version", version="fetch 1.0")
parser.add_argument("urls", nargs="+", metavar="URL")
parser.add_argument("--retries", type=int, default=3)
parser.add_argument("--format", choices=["json", "csv"], default="json")
parser.add_argument("-H", "--header", action="append", default=[])
parser.add_argument("--color", action=argparse.BooleanOptionalAction,
                    default=True)
output = parser.add_mutually_exclusive_group()
output.add_argument("-q", "--quiet", action="store_true")
output.add_argument("-o", "--output", metavar="FILE")

args = parser.parse_args(["-vv", "--format", "csv", "-H", "A: 1",
                          "-H", "B: 2", "--no-color", "https://a.example"])
for name, value in vars(args).items():
    print(f"{name:<8} {value!r}")
```

```text
verbose  2
urls     ['https://a.example']
retries  3
format   'csv'
header   ['A: 1', 'B: 2']
color    False
quiet    False
output   None
```

`count` turns `-vv` into 2. `nargs="+"` wants one or more values (`"*"` allows none, `"?"` at most one). `choices` rejects anything else with exit code 2. `append` collects a repeated option into a list. `BooleanOptionalAction` makes `--color` and `--no-color` from one call. A mutually exclusive group refuses `-q -o out.json`. `--version` prints and exits 0, and `parents=` shares options between parsers, such as subcommands.

<Since v="3.15" /> When an option has a short and a single-dash long name, `dest` now comes from the long one: `add_argument("-f", "-foo")` stores `foo`, where 3.14 stored `f`. Pass `dest=` explicitly if your code reads the old name.

## Pipes, Ctrl-C and standard input

Shell users will pipe your tool into `head`, feed it from another program and press Ctrl-C. `numlines`, which numbers the lines of its files, handles all three:

```python title="numlines.py"
import argparse
import os
import sys


def lines_of(name):
    """Yield the lines of a file, or of standard input for "-"."""
    if name == "-":
        yield from sys.stdin
    else:
        with open(name, encoding="utf-8") as file:
            yield from file


def number_lines(names):
    number = 1
    for name in names:
        for line in lines_of(name):
            print(f"{number:>4}  {line}", end="")
            number += 1
```

```python title="numlines.py (continued)"
def main(argv=None):
    parser = argparse.ArgumentParser(prog="numlines")
    parser.add_argument("files", nargs="*", default=["-"],
                        help="files to number; - or none reads stdin")
    args = parser.parse_args(argv)
    try:
        number_lines(args.files)
        sys.stdout.flush()
    except KeyboardInterrupt:
        return 130  # 128 + SIGINT, what shells expect after Ctrl-C
    except BrokenPipeError:  # the reader left, as `head` does
        os.dup2(os.open(os.devnull, os.O_WRONLY), sys.stdout.fileno())
        return 1
    except OSError as error:  # after BrokenPipeError, its subclass
        print(f"numlines: {error.filename}: {error.strerror}",
              file=sys.stderr)
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

```console
$ printf 'alpha\nbeta\n' | python numlines.py
   1  alpha
   2  beta
$ python numlines.py big.txt | head -1
   1  line
$ python numlines.py nope.txt
numlines: nope.txt: No such file or directory
```

The `-` convention, and reading stdin when no file is given, lets the tool sit in the middle of a pipeline. When `head` exits after one line, the next write fails with `BrokenPipeError`; without the handler that is a traceback. The `dup2` line comes from the [signal documentation](https://docs.python.org/3/library/signal.html#note-on-sigpipe): it points stdout at `/dev/null`, so the flush Python does on exit cannot fail a second time. Ctrl-C raises `KeyboardInterrupt`; catching it replaces the traceback with a quiet exit 130, the code shells report for a program stopped by SIGINT (128 plus signal 2). Avoid `argparse.FileType` for `-`: it is deprecated since 3.14, and leaves files open when a later argument fails.

## Colour and suggestions

<Since v="3.14" /> `argparse` prints help and errors in colour on a terminal. `color=False` switches it off for one program, `NO_COLOR` for all of them, and `FORCE_COLOR` or `PYTHON_COLORS=1` forces it. Colour is never written into a pipe unless forced, so the outputs here are plain.

<Since v="3.15" /> Mistyped subcommands and choices now get a suggestion by default (the `suggest_on_error` parameter, added in 3.14, now defaults to `True`):

```python title="todo_suggest.py"
import contextlib
import sys

from todo.cli import build_parser

parser = build_parser()
with contextlib.redirect_stderr(sys.stdout):
    try:
        parser.parse_args(["lst"])
    except SystemExit as exit_request:
        print("[exit", str(exit_request.code) + "]")
```

```text
usage: todo [-h] [--file FILE] {add,list,done} ...
todo: error: argument command: invalid choice: 'lst', maybe you meant 'list'? (choose from 'add', 'list', 'done')
[exit 2]
```

Also new in 3.15: text in backticks inside `description`, `epilog` or `help` strings is highlighted when colour is on, and printed as is when it is off. When you retire an option, `add_argument(..., deprecated=True)` <Since v="3.13" /> keeps it working and prints a warning each time it is used.

## When not to use argparse like this

For a ten-line script you run yourself, `sys.argv[1]` is fine. Do not add subcommands to a tool that does one thing: three flags are simpler than three verbs. For large tools with nested command groups, shell completion or rich prompts, third-party libraries such as Click or Typer save code, though they are another dependency. And if the "CLI" is really a configuration file in disguise, with twenty options on every run, accept a TOML file instead.

## Common pitfalls

- **Calling `sys.exit` deep inside handlers.** It makes them untestable. Raise an exception and translate it in `main`.
- **Printing errors to stdout.** They end up in the next program's input.
- **Exit code 0 on failure.** Scripts and CI check the code, not the words.
- **Heavy imports at the top of the CLI module.** `--help` pays for them. See [lazy imports](../../intermediate/lazy-imports/).

Write a `unittest` file that calls `main` directly, in the style of the [test-driven workflow lesson](../../intermediate/test-driven-workflow/). Use a temporary folder for the task file. Test three things: `add` then `list` prints ` 1 [ ] Ship it` with nothing on stderr; `done 3` on an empty list exits 1 with the message on stderr; `done` with no number exits 2.

Expected, from `python -m unittest -v test_todo_cli.py`:

```text
test_add_then_list (test_todo_cli.TodoCliTest.test_add_then_list) ... ok
test_bad_usage_is_exit_2 (test_todo_cli.TodoCliTest.test_bad_usage_is_exit_2) ... ok
test_unknown_task_is_exit_1_on_stderr (test_todo_cli.TodoCliTest.test_unknown_task_is_exit_1_on_stderr) ... ok

----------------------------------------------------------------------
Ran 3 tests in 0.001s

OK
```

<Solution>

```python title="test_todo_cli.py"
import contextlib
import io
import tempfile
import unittest
from pathlib import Path

from todo.cli import main


def run(*argv):
    """Call main() in-process and return (exit code, stdout, stderr)."""
    out, err = io.StringIO(), io.StringIO()
    with contextlib.redirect_stdout(out), contextlib.redirect_stderr(err):
        try:
            code = main(list(argv))
        except SystemExit as exit_request:
            code = exit_request.code
    return code, out.getvalue(), err.getvalue()
```

```python title="test_todo_cli.py (continued)"
class TodoCliTest(unittest.TestCase):
    def setUp(self):
        folder = tempfile.TemporaryDirectory()
        self.addCleanup(folder.cleanup)
        self.file = str(Path(folder.name, "todo.json"))

    def test_add_then_list(self):
        run("--file", self.file, "add", "Ship it")
        code, out, err = run("--file", self.file, "list")
        self.assertEqual((code, out, err), (0, " 1 [ ] Ship it\n", ""))

    def test_unknown_task_is_exit_1_on_stderr(self):
        code, out, err = run("--file", self.file, "done", "3")
        self.assertEqual((code, out), (1, ""))
        self.assertIn("no task #3", err)

    def test_bad_usage_is_exit_2(self):
        code, _, err = run("--file", self.file, "done")
        self.assertEqual(code, 2)
        self.assertIn("usage: todo done", err)


if __name__ == "__main__":
    unittest.main()
```

The `run` helper is the whole trick: because `main` takes `argv` and returns a code, a test needs no subprocess. Catching `SystemExit` covers argparse's usage errors. Keep one or two subprocess tests as well, to check the installed command and `__main__.py`.

</Solution>
</Exercise>

```python title="notes_cli.py"
def show(args):

parser = argparse.ArgumentParser(prog="notes")
sub = parser.add_subparsers(dest="command")
```

Explain the crash and fix it so that the empty command line is a usage error with exit code 2. Print the exit code instead of letting `SystemExit` end the loop. Expected output, with stderr shown:

```text
showing notes
usage: notes [-h] {show} ...
```

```python title="notes_cli_fixed.py"
import argparse
import contextlib
import sys


def show(args):
    print("showing notes")


parser = argparse.ArgumentParser(prog="notes")
sub = parser.add_subparsers(dest="command", required=True)
sub.add_parser("show").set_defaults(handler=show)

with contextlib.redirect_stderr(sys.stdout):
    for argv in (["show"], []):
        try:
            args = parser.parse_args(argv)
            args.handler(args)
        except SystemExit as exit_request:
            print("[exit", str(exit_request.code) + "]")
```

```text
showing notes
usage: notes [-h] {show} ...
notes: error: the following arguments are required: command
[exit 2]
```

Subcommands are optional unless you say otherwise. With no subcommand, no subparser ran, so no `set_defaults` ever put `handler` into the namespace. `required=True` makes the missing subcommand a usage error. It needs `dest=` as well, or the message has no name to report.

## Summary

- Write `main(argv=None) -> int`. Handlers raise; `main` turns known errors into one line on stderr and an exit code.
- `add_subparsers(dest=..., required=True)` with `set_defaults(handler=...)` gives clean subcommand dispatch.
- Exit 0 for success, 1 for failure, 2 for bad usage. Results on stdout, problems on stderr.
- `__main__.py` enables `python -m pkg`; `[project.scripts]` installs a command.
- `choices`, `nargs`, `count`, `append`, exclusive groups and `--version` cover most options. In 3.15, `dest` comes from a single-dash long option.
- Treat `-` as stdin, catch `BrokenPipeError` (then point stdout at `/dev/null`) and return 130 on `KeyboardInterrupt`.
- Help is coloured from 3.14 (`color=False`, `NO_COLOR`), and 3.15 suggests corrections for typos.
